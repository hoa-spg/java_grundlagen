1 — Was ist ein Stream?

Die Streams-API erlaubt es, viele häufige Operationen (meist mit Lambdas aus Lektion 3.5) sehr kurz und prägnant anzuschreiben – das erspart zahlreiche Schleifen. Der Stil ist von der funktionalen Programmierung geprägt und kam deshalb in der objektorientierten Sprache Java erst mit Version 8. Der wichtigste Unterschied zur Schleife: Du beschreibst, was herauskommen soll, nicht wie es Schritt für Schritt berechnet wird.

Beispiel: die Namen aller Personen mit Kosten über 2000 Euro, alphabetisch sortiert – zuerst mit Schleife, dann mit Stream:

mit Schleife Java 
List<String> namen = new ArrayList<>();
for (Person p : personal) {
    if (p.getKostenProMonat() > 2000) {
        namen.add(p.getName());
    }
}
Collections.sort(namen);
mit Stream Java 
List<String> namen = personal.stream()
    .filter(p -> p.getKostenProMonat() > 2000)
    .map(Person::getName)
    .sorted()
    .toList();

Die Stream-Variante liest sich wie ein Satz: Nimm das Personal, behalte die mit Kosten über 2000, nimm davon die Namen, sortiere sie, mach eine Liste daraus. Typisch ist der fluent-Stil mit verketteten Methodenaufrufen (method chaining): Jeder Aufruf liefert wieder einen Stream, auf dem direkt die nächste Methode aufgerufen wird. Man spricht von einer Pipeline:

personal.stream()Quelle → filter(…)Zwischenoperation → map(…)Zwischenoperation → sorted()Zwischenoperation → toList()Endoperation → List<String>Ergebnis

Ein Stream ist ein „Datenstrom“ mit den Objekten einer Collection, die nacheinander abgearbeitet werden. Er speichert selbst keine Daten und verändert die Collection nicht; personal ist nach der Pipeline genau wie vorher. Erzeugt wird ein Stream meist mit stream():

Streams erzeugen Java 
personal.stream()                  // aus einer Collection
Arrays.stream(new int[] {3, 1, 4}) // aus einem Array
Stream.of("Anna", "Bert")          // aus einzelnen Werten
IntStream.rangeClosed(1, 5)        // die Zahlen 1, 2, 3, 4, 5
ℹ
toList() oder collect(Collectors.toList())?
toList() gibt es seit Java 16 und liefert eine unveränderliche Liste. In älterem Code (und im Projekt) findest du collect(Collectors.toList()), das eine veränderbare ArrayList liefert. Für reine Auswertungen sind beide gleichwertig.

2 — Zwischen- und Endoperationen

Eine Pipeline besteht aus beliebig vielen Zwischenoperationen, die wieder einen Stream liefern, und genau einer Endoperation, die ein Ergebnis liefert (eine Liste, eine Zahl …) oder eine Aktion ausführt.

OperationArtWirkung
filter(p -> …)Zwischenoperationbehält nur Elemente, für die die Bedingung gilt
map(x -> …), mapToInt(…)Zwischenoperationbildet jedes Element auf einen neuen Wert ab
sorted(), sorted(comparator)Zwischenoperationsortiert
distinct(), limit(n)Zwischenoperationentfernt Duplikate bzw. behält nur die ersten n Elemente
toList(), collect(…)Endoperationsammelt in eine Liste, einen String, eine Map … (Abschnitt 5)
count(), sum(), max(), average()Endoperationzählt bzw. berechnet
anyMatch(…), allMatch(…), noneMatch(…)Endoperationprüft, ob mindestens eines / alle / keines der Elemente die Bedingung erfüllt
findFirst()Endoperationliefert das erste Element (als Optional, Abschnitt 4)
forEach(x -> …)Endoperationführt eine Aktion für jedes Element aus
Pipelines Java 
// Namen aller Freelancer, alphabetisch, als ein String
String freelancer = personal.stream()
                            .filter(p -> p instanceof Freelancer)
                            .map(Person::getName)
                            .sorted()
                            .collect(Collectors.joining(", "));

// Gibt es jemanden, der vor 1960 geboren ist?
boolean alt = personal.stream().anyMatch(p -> p.getGeburtsjahr() < 1960);

// Verdienen alle mindestens 1000 Euro?
boolean alleUeber1000 = personal.stream().allMatch(p -> p.getKostenProMonat() >= 1000);

// die drei teuersten Personen ausgeben
personal.stream()
        .sorted((a, b) -> b.getKostenProMonat() - a.getKostenProMonat())
        .limit(3)
        .forEach(System.out::println);

instanceof prüft, ob ein Objekt zu einer Klasse (oder Unterklasse) gehört. map kann den Typ ändern: Aus einem Stream von Person wird ein Stream von String. Ein Stream kann nur einmal durchlaufen werden – für eine zweite Auswertung erzeugt man einfach mit stream() einen neuen.

3 — Lazy Evaluation: Wie ein Stream abgearbeitet wird

Man könnte meinen, filter geht zuerst alle Elemente durch, dann map alle übrigen usw. Tatsächlich wandert jedes Element einzeln durch die ganze Pipeline, und zwar erst dann, wenn die Endoperation ein Ergebnis braucht (Lazy Evaluation, dt. verzögerte Auswertung). Mit peek, das jedes Element nur „anschaut“, lässt sich das sichtbar machen:

Lazy Evaluation sichtbar machen Java 
// personal: Susanne Huber (2500), Karl Maier (2600), Sepp Gruber (900), Eva Maier (2280)
List<String> namen = personal.stream()
        .peek(p -> System.out.println("filter: " + p.getName()))
        .filter(p -> p.getKostenProMonat() > 2000)
        .peek(p -> System.out.println("  map:  " + p.getName()))
        .map(Person::getName)
        .limit(2)
        .toList();
System.out.println(namen);
Ausgabe Text 
filter: Susanne Huber
  map:  Susanne Huber
filter: Karl Maier
  map:  Karl Maier
[Susanne Huber, Karl Maier]

Sepp Gruber und Eva Maier werden gar nicht mehr angesehen: Nach zwei Treffern ist limit(2) erfüllt und der Stream hört auf. Ohne Endoperation (toList()) würde überhaupt nichts ausgegeben. peek ist nur zum Nachvollziehen und Debuggen gedacht – im fertigen Code hat es nichts verloren.

4 — Zahlen-Streams und Optional

Für Berechnungen gibt es eigene Zahlen-Streams (IntStream, DoubleStream), die man mit mapToInt bzw. mapToDouble erhält. Sie kennen sum(), max(), min() und average():

mapToInt, sum, max, average Java 
int summe = personal.stream()
                    .mapToInt(Person::getKostenProMonat)
                    .sum();

int hoechsteNummer = personal.stream()
                             .mapToInt(Person::getPersonalNummer)
                             .max()
                             .orElseThrow(NoSuchElementException::new);

double schnitt = personal.stream()
                         .mapToInt(Person::getGeburtsjahr)
                         .average()
                         .orElse(0);

// alles auf einmal: Anzahl, Summe, Minimum, Durchschnitt, Maximum
IntSummaryStatistics stat = personal.stream()
                                    .mapToInt(Person::getKostenProMonat)
                                    .summaryStatistics();
System.out.println(stat.getMax() + " / " + stat.getAverage());

Bei einer leeren Liste gibt es kein Maximum und keinen Durchschnitt. max(), average() und findFirst() liefern deshalb ein Optional – eine „Schachtel“, die einen Wert enthalten kann oder leer ist. So erzwingt der Compiler, dass du dir überlegst, was bei einer leeren Liste passieren soll. sum() und count() liefern bei einer leeren Liste einfach 0.

Methode von OptionalWirkung
orElse(wert)Inhalt oder – wenn leer – der Ersatzwert
orElseThrow(…)Inhalt oder – wenn leer – eine Exception
isPresent(), isEmpty()prüft, ob ein Wert enthalten ist
map(…)wandelt den Inhalt um, falls vorhanden
Optional bei Objekten Java 
String teuerste = personal.stream()
                          .max(Comparator.comparing(Person::getKostenProMonat))
                          .map(Person::getName)
                          .orElse("niemand");               // "Karl Maier"

String ersterMaier = personal.stream()
                             .map(Person::getName)
                             .filter(n -> n.endsWith("Maier"))
                             .findFirst()
                             .orElse("-");                  // "Karl Maier"

IntStream.range ersetzt einfache Zählschleifen: IntStream.range(0, 5) liefert 0 bis 4, rangeClosed(1, 5) 1 bis 5 (inklusive).

IntStream.range Java 
int quadratsumme = IntStream.rangeClosed(1, 5)
                            .map(i -> i * i)
                            .sum();                          // 1 + 4 + 9 + 16 + 25 = 55

5 — Sammeln und Gruppieren mit Collectors

collect nimmt einen Collector, der festlegt, wie die Elemente zusammengefasst werden. Die Klasse Collectors bietet fertige Collectors an – neben toList() und joining vor allem zum Gruppieren: Das Ergebnis ist eine Map, deren Schlüssel die Gruppen sind.

groupingBy und partitioningBy Java 
// Anzahl Personen pro Typ
Map<String, Long> anzahlProTyp = personal.stream()
        .collect(Collectors.groupingBy(p -> p.getClass().getSimpleName(),
                                       Collectors.counting()));
// {Arbeiter=1, Freelancer=1, Angestellter=2}

// Namen pro Typ
Map<String, List<String>> namenProTyp = personal.stream()
        .collect(Collectors.groupingBy(p -> p.getClass().getSimpleName(),
                                       Collectors.mapping(Person::getName,
                                                          Collectors.toList())));
// {Angestellter=[Susanne Huber, Eva Maier], Arbeiter=[Karl Maier], Freelancer=[Sepp Gruber]}

// in genau zwei Gruppen teilen: true / false
Map<Boolean, List<Person>> teuer = personal.stream()
        .collect(Collectors.partitioningBy(p -> p.getKostenProMonat() > 2400));
CollectorErgebnis
Collectors.toList(), toSet()Liste bzw. Menge
Collectors.joining(", ")ein String (nur für Streams von Strings)
Collectors.groupingBy(schlüssel)Map<Schlüssel, List<Element>>
Collectors.groupingBy(schlüssel, Collectors.counting())Map<Schlüssel, Long> mit der Anzahl pro Gruppe
Collectors.groupingBy(schlüssel, Collectors.summingInt(…))Summe pro Gruppe
Collectors.partitioningBy(bedingung)Map<Boolean, List<Element>>

groupingBy liefert eine HashMap; die Reihenfolge der Schlüssel bei der Ausgabe ist daher nicht festgelegt. Für sortierte Schlüssel übergibt man TreeMap::new als zweites Argument: groupingBy(schlüssel, TreeMap::new, Collectors.counting()).

Stream oder Schleife?

Streams sind ideal für Auswertungen: filtern, umwandeln, zählen, sammeln, gruppieren. Muss man dagegen während des Durchlaufs Objekte verändern, Exceptions behandeln oder mit dem Index arbeiten, ist eine normale Schleife oft lesbarer. Beides ist richtig – wähle, was sich besser liest. Streams sind ein umfangreiches Kapitel der modernen Java-Programmierung; diese Lektion zeigt die wichtigsten Werkzeuge.

Projektschritt

Projektschritt 3.6

Auswertungen mit Streams

Die Firma bekommt Auswertungen in wenigen Zeilen: Filtern nach Kosten, Zählen der Freelancer und eine sortierte Namensliste. summeKosten() wird mit einem Stream statt einer Schleife berechnet.

src/main/java/Firma.java (Auszug) Java 
public int summeKosten() {
    // Stream statt Schleife: jede Person -> Kosten (int), dann aufsummieren
    return personal.stream()
                   .mapToInt(p -> p.getKostenProMonat())
                   .sum();
}

public List<Person> personalMitKostenUeber(int minKosten) {
    return personal.stream()
                   .filter(p -> p.getKostenProMonat() > minKosten)
                   .collect(Collectors.toList());
}

public long anzahlFreelancer() {
    return personal.stream()
                   .filter(p -> p instanceof Freelancer)
                   .count();
}

public List<String> namen() {
    return personal.stream()
                   .map(Person::getName)
                   .sorted()
                   .collect(Collectors.toList());
}

Das Hauptprogramm gibt die Auswertungen aus und nutzt für die nach Kosten sortierte Liste aus Lektion 3.5 eine Pipeline mit map und forEach. StreamTest prüft alle neuen Methoden.

Häufige Fehler

5 Fehler · zum Aufklappen klicken
Fehler: Stream ohne Endoperation

personal.stream().filter(…).map(…); bewirkt nichts.

Wegen der Lazy Evaluation passiert erst etwas bei einer Endoperation (collect, count, forEach, sum …).

Fehler: Stream zweimal verwendet

Stream<Person> s = personal.stream(); s.count(); s.count(); → IllegalStateException: stream has already been operated upon or closed.

Für jede Auswertung mit personal.stream() einen neuen Stream erzeugen.

Fehler: Checked Exception im Lambda

personal.forEach(p -> p.setName(…)); → unreported exception FirmaException.

Die Methoden der Stream-/Collection-API erlauben keine checked Exceptions im Lambda. Innerhalb des Lambdas mit try/catch behandeln oder in eine RuntimeException verpacken (siehe Company.increaseSalaryByPercent, Lektion 3.8) – oder eine normale Schleife verwenden.

Fehler: toList()-Ergebnis verändert

List<Person> l = personal.stream().filter(…).toList(); l.add(p); → UnsupportedOperationException.

toList() liefert eine unveränderliche Liste. Soll die Liste verändert werden: collect(Collectors.toList()) oder new ArrayList<>(…toList()).

Fehler: Optional statt Zahl

int max = personal.stream().mapToInt(…).max(); → incompatible types: OptionalInt cannot be converted to int.

max() liefert ein Optional. Mit .orElse(0) oder .orElseThrow() den Wert herausholen.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was gilt für einen Stream?

Erklärung: Ein Stream ist keine Datensammlung, sondern eine Pipeline. Nach der Endoperation ist er verbraucht; die Quelle bleibt unverändert.

Frage 2 Welche Operationen sind Zwischenoperationen?

Mehrere Antworten sind richtig.

Erklärung: Zwischenoperationen liefern wieder einen Stream und lassen sich verketten. count, collect, forEach oder toList sind Endoperationen und liefern ein Ergebnis.

Frage 3 Warum liefert mapToInt(…).max() ein OptionalInt und nicht einfach ein int?

Erklärung: Ein Optional macht sichtbar, dass vielleicht kein Wert existiert. Mit orElse(0) oder isPresent() entscheidet man, was dann passieren soll.

Frage 4 Was liefert personen.stream().collect(Collectors.groupingBy(Person::getAbteilung))?

Erklärung: groupingBy ordnet jedes Element einem Schlüssel zu und sammelt die Elemente je Schlüssel. partitioningBy teilt dagegen nur in zwei Gruppen (true/false).
