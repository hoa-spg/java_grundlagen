1 — Serialisierung

Serialisierung bedeutet, dass Objekte (die als Daten im Hauptspeicher vorliegen) in eine sequentielle Form gebracht werden, die es ermöglicht, sie in Dateien zu schreiben oder über das Netzwerk zu übertragen. Die erste der folgenden Methoden speichert die Firma samt ihrer Mitarbeiter in einem binären Format in einer Datei. Mit der zweiten wird das Firmen-Objekt mit allen Mitarbeitern wieder hergestellt – auch nach einem Neustart des Programms oder auf einem anderen Rechner, da alle nötigen Daten in der Datei stehen.

Firma.java – Serialisierung mit finally Java 
public void serialize() throws FirmaException {
    ObjectOutputStream oos = null;
    try {
        oos = new ObjectOutputStream(new FileOutputStream("firma.ser"));
        oos.writeObject(this);
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    } finally {
        try {
            if (oos != null) {
                oos.flush();
                oos.close();
            }
        } catch (IOException e) {
            throw new FirmaException("I/O Error: " + e.getMessage());
        }
    }
}

public static Firma deserialize() throws FirmaException {
    Firma firma = null; // implements Serializable
    ObjectInputStream ois = null;
    try {
        ois = new ObjectInputStream(new FileInputStream("firma.ser"));
        firma = (Firma) ois.readObject();
    } catch (FileNotFoundException e) {
        throw new FirmaException("Datei nicht gefunden. " + e.getMessage());
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    } catch (ClassNotFoundException e) {
        throw new FirmaException("Fehler bei der Konvertierung. "
                                 + e.getMessage());
    } finally {
        try {
            if (ois != null) {
                ois.close();
            }
        } catch (IOException e) {
            throw new FirmaException("I/O Error: " + e.getMessage());
        }
    }
    return firma;
}

Verwendet werden ObjectOutputStream in Kombination mit FileOutputStream sowie ObjectInputStream mit FileInputStream. Der wesentliche Code ist oos.writeObject(this) – das aktuelle Objekt wird in den Stream geschrieben – und (Firma) ois.readObject() zum Einlesen; dabei ist eine explizite Typkonvertierung nötig.

Der restliche Code betrifft die Ausnahmebehandlung: Beim Schreiben oder Lesen kann es zu Ausnahmefällen kommen – volle Festplatte, entfernter USB-Stick, fehlende Schreibrechte u. v. m. Die Streams müssen jedenfalls geschlossen werden, was im finally-Block passiert. Da auch dabei Ausnahmen auftreten können, enthält er wiederum ein try-catch – zugegeben umständlich.

⚠
NotSerializableException

Bei der Ausführung erhält man zunächst eine NotSerializableException: Es ist nicht sichergestellt, dass sich die betroffenen Objekte tatsächlich serialisieren lassen. Dazu müssen alle beteiligten Klassen (Firma, Person und damit alle Unterklassen) das Interface Serializable implementieren. Es enthält keine Methoden – es ist ein Marker-Interface, das angibt, dass die Klasse sinnvoll serialisiert werden kann.

2 — try-with-resources

Mit dem try-with-resources-Statement geht es kompakter. Ressourcen sind Objekte, die nach der Verwendung geschlossen werden müssen; sie werden in runden Klammern direkt nach try angegeben und am Ende automatisch geschlossen. Der finally-Block entfällt.

Firma.java – mit try-with-resources Java 
public void serialize() throws FirmaException {
    try (FileOutputStream fos = new FileOutputStream("firma.ser");
         ObjectOutputStream oos = new ObjectOutputStream(fos))
    {
        oos.writeObject(this);
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    }
}

public static Firma deserialize() throws FirmaException {
    Firma firma = null;
    try (FileInputStream fis = new FileInputStream("firma.ser");
         ObjectInputStream ois = new ObjectInputStream(fis))
    {
        firma = (Firma) ois.readObject();
    } catch (FileNotFoundException e) {
        throw new FirmaException("Datei nicht gefunden. " + e.getMessage());
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    } catch (ClassNotFoundException e) {
        throw new FirmaException("Fehler bei der Konvertierung. "
                                 + e.getMessage());
    }
    return firma;
}
  • Mit dem Schlüsselwort transient werden Attribute markiert, die nicht (de-)serialisiert werden sollen (z. B. Passwörter, Caches).
  • Mit private static final long serialVersionUID = 42L; vergibt man eine „Versionsnummer“ für die Klasse, um die Kompatibilität mit bestimmten Softwareversionen sicherzustellen. Ändert sich die Klasse inkompatibel, erhöht man sie – alte Dateien werden dann mit einer klaren Fehlermeldung abgewiesen.
  • Die Reihenfolge der catch-Blöcke ist wichtig: FileNotFoundException ist eine Unterklasse von IOException und muss daher vorher stehen.

3 — Textdateien im CSV-Format

Die serialisierte Datei ist für Menschen nicht (oder nur teilweise) lesbar – ein Binärformat. Oft möchte man aber human-readable Textdateien schreiben, z. B. xml, json oder csv. CSV steht für Comma-Separated Values: Die Elemente einer Zeile sind durch ein Trennzeichen getrennt, im deutschen Sprachraum meist ; (oft auch ,). Solche Dateien lassen sich mit Texteditoren bearbeiten, aber auch mit Tabellenkalkulationen wie Excel, die die Trennzeichen als Spalten interpretieren.

firma.csv CSV 
Spengergasse OG
Arbeiter;Karl;1989;15;40;Hilfsarbeiter
Angestellter;Susanne;1991;20;30;keine Ueberstundenpauschale
Freelancer;Sepp;1981;3;300

Zum Schreiben und Lesen erweitern wir die Klasse Firma:

Firma.java – CSV schreiben und lesen Java 
public void writeToFile(String filename) throws FirmaException {
    try (FileWriter fw = new FileWriter(filename);
         BufferedWriter bw = new BufferedWriter(fw))
    {
        bw.write(this.toCSVString());
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    }
}

public static Firma readFromFile(String filename) throws FirmaException {
    Firma firma = null;
    try (FileReader fr = new FileReader(filename);
         BufferedReader br = new BufferedReader(fr))
    {
        String line = br.readLine();
        if (line == null || line.isEmpty() || line.isBlank()) {
            throw new FirmaException("Ungueltige Eingabedatei: "
                         + " ungueltiger Firmenname in erster Zeile");
        }
        firma = new Firma(line);
        line = br.readLine();
        while (line != null) {

            Person p = null;
            if (line.startsWith("Arbeiter")) {
                p = new Arbeiter(line);
            } else if (line.startsWith("Angestellter")) {
                p = new Angestellter(line);
            } else if (line.startsWith("Freelancer")) {
                p = new Freelancer(line);
            } else {
                throw new FirmaException("Ungueltiger Mitarbeitertyp in Zeile "
                                         + line);
            }
            firma.einstellen(p);
            line = br.readLine();
        }
    } catch (FileNotFoundException e) {
        throw new FirmaException("File " + filename + " not found. "
                                 + e.getMessage());
    } catch (IOException e) {
        throw new FirmaException("I/O Error: " + e.getMessage());
    }
    return firma;
}

Diese Methoden setzen voraus, dass die beteiligten Klassen (Firma, Arbeiter, Angestellter, Freelancer) jeweils toCSVString() enthalten und Konstruktoren haben, die ein Objekt aus einem einzelnen CSV-String erzeugen.

Schreiben: toCSVString über die ganze Hierarchie

Firma.java Java 
public String toCSVString() {
    String s = getName() + "\n";
    for (Person p : personal) {
        s += p.toCSVString() + "\n";
    }
    return s;
}

Dabei wird für jede Person ebenfalls toCSVString() aufgerufen – dank Polymorphismus die passende Version:

Arbeiter.java Java 
@Override
public String toCSVString() {
    return super.toCSVString() + ";"
           + (isFacharbeiter() ? "Facharbeiter"
                               : "Hilfsarbeiter");
}
Mitarbeiter.java Java 
@Override
public String toCSVString() {
    return super.toCSVString() + ";" + getStundenlohn()
           + ";" + getAnzahlWochenStunden();
}
Person.java Java 
public String toCSVString() {
    return this.getClass().getName() + ";" + getName() + ";" + getGeburtsjahr();
}

Jede Ebene ruft die Methode der Basisklasse auf und hängt ihre eigenen Spalten an. Person schreibt mit this.getClass().getName() den Namen der (tatsächlichen!) Klasse in die erste Spalte – daran erkennt readFromFile später, welches Objekt zu erzeugen ist.

Lesen: Konstruktor mit CSV-Zeile

readFromFile prüft zuerst die erste Zeile und erzeugt daraus (falls nicht null und nicht leer) die Firma. In der while-Schleife werden die weiteren Zeilen gelesen; die If-Bedingungen unterscheiden den Mitarbeitertyp, und der Konstruktor mit einem String-Parameter erzeugt das Objekt. Bei Angestellter:

Angestellter.java Java 
public Angestellter(String csv) throws FirmaException {
    String[] tokens = csv.split(";");
    if (tokens.length != 6) {
        throw new FirmaException("Ungueltige Zeile: " + csv
                                 + ". 6 Spalten erwartet.");
    }

    String name = tokens[1];
    setName(name);

    int geburtsjahr = 0;
    try {
        geburtsjahr = Integer.parseInt(tokens[2]);
    } catch (NumberFormatException e) {
        throw new FirmaException("Ungueltige Zeile: " + csv
                    + ". Geburtsjahr in der 3. Spalte erwartet.");
    }
    setGeburtsjahr(geburtsjahr);

    int stundenlohn;
    try {
        stundenlohn = Integer.parseInt(tokens[3]);
    } catch (NumberFormatException e) {
        throw new FirmaException("Ungueltige Zeile: " + csv
                    + ". Stundenlohn in der 4. Spalte erwartet.");
    }
    setStundenlohn(stundenlohn);

    int anzahlWochenstunden;
    try {
        anzahlWochenstunden = Integer.parseInt(tokens[4]);
    } catch (NumberFormatException e) {
        throw new FirmaException("Ungueltige Zeile: " + csv
                     + ". Anzahl Wochenstunden in der 5. Spalte erwartet.");
    }
    setAnzahlWochenStunden(anzahlWochenstunden);

    boolean ueberstundenpauschale = true;
    if (tokens[5] != null && tokens[5].equals("keine Ueberstundenpauschale")) {
        ueberstundenpauschale = false;
    } else if (tokens[5] != null && tokens[5].equals("Ueberstundenpauschale")) {
        ueberstundenpauschale = true;
    } else {
        throw new FirmaException("Ungueltige Zeile: " + csv
                    + ". Info zu Ueberstundenpauschale in 6. Spalte erwartet.");
    }
    setUeberstundenPauschale(ueberstundenpauschale);
}

Zuerst wird der CSV-String mit split(";") anhand des Trennzeichens in einzelne Tokens zerlegt; jedes Array-Element enthält danach eine Spalte. Dann werden die Elemente geprüft und im Fehlerfall Exceptions geworfen. Integer.parseInt wirft eine NumberFormatException, wenn der String keine ganze Zahl ist; sie wird gefangen und in eine FirmaException „umgewandelt“.

Projektschritt

Projektschritt 3.3

Speichern und Laden der Personalverwaltung

Firma und Person implementieren Serializable (mit serialVersionUID); serialize/deserialize nehmen den Dateinamen als Parameter. Alle Klassen haben toCSVString(), und Angestellter, Arbeiter und Freelancer haben CSV-Konstruktoren. Um die sich wiederholenden try/catch-Blöcke für Zahlen zu vermeiden, gibt es in Person eine Hilfsmethode (Code-Wiederverwendung):

src/main/java/Person.java (Auszug) Java 
// Hilfsmethode für die CSV-Konstruktoren der Unterklassen:
// wandelt eine Spalte in eine Zahl um, sonst FirmaException
protected static int zahlAusCsv(String wert, String spalte, String csv)
    throws FirmaException
{
    try {
        return Integer.parseInt(wert.trim());
    } catch (NumberFormatException e) {
        throw new FirmaException("Ungueltige Zeile: " + csv + ". " + spalte
                                 + " muss eine ganze Zahl sein.", e);
    }
}
src/main/java/Arbeiter.java (Auszug) Java 
// CSV-Zeile: Arbeiter;Karl Maier;1989;15;40;Facharbeiter
public Arbeiter(String csv) throws FirmaException {
    String[] tokens = csv.split(";");
    if (tokens.length != 6) {
        throw new FirmaException("Ungueltige Zeile: " + csv + ". 6 Spalten erwartet.");
    }
    setName(tokens[1]);
    setGeburtsjahr(zahlAusCsv(tokens[2], "Geburtsjahr (3. Spalte)", csv));
    setStundenlohn(zahlAusCsv(tokens[3], "Stundenlohn (4. Spalte)", csv));
    setAnzahlWochenStunden(zahlAusCsv(tokens[4], "Wochenstunden (5. Spalte)", csv));
    if (tokens[5].equals("Facharbeiter")) {
        setFacharbeiter(true);
    } else if (tokens[5].equals("Hilfsarbeiter")) {
        setFacharbeiter(false);
    } else {
        throw new FirmaException("Ungueltige Zeile: " + csv
                    + ". Facharbeiter/Hilfsarbeiter in 6. Spalte erwartet.");
    }
}

protected heißt: sichtbar in der Klasse und in allen Unterklassen. Im Projektordner liegt eine Beispieldatei, die Programm einliest, erweitert, als CSV und binär speichert und wieder lädt. DateiTest schreibt in einen temporären Ordner (@TempDir).

Angestellter;Susanne Huber;1991;20;30;keine Ueberstundenpauschale
Arbeiter;Karl Maier;1989;15;40;Facharbeiter
Freelancer;Sepp Gruber;1981;3;300
Angestellter;Eva Maier;1995;18;38;Ueberstundenpauschale

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: NotSerializableException

java.io.NotSerializableException: Arbeiter beim Serialisieren der Firma.

Alle Klassen, deren Objekte mitgeschrieben werden (auch über Attribute erreichbare), müssen Serializable implementieren – es genügt, das bei der Basisklasse Person zu tun.

Fehler: Datei nicht gefunden

FileNotFoundException: firma.csv, obwohl die Datei existiert.

Relative Pfade beziehen sich auf das Arbeitsverzeichnis beim Programmstart (in IntelliJ meist der Projektordner, nicht src). Datei dorthin legen oder den Pfad in der Run-Konfiguration prüfen.

Fehler: Spalten falsch gezählt

ArrayIndexOutOfBoundsException bei tokens[5] für eine Freelancer-Zeile.

Vor dem Zugriff tokens.length prüfen; jede Klasse hat ihre eigene Spaltenanzahl (Freelancer 5, Arbeiter/Angestellter 6). Indizes beginnen bei 0 – die 3. Spalte ist tokens[2].

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was bedeutet Serialisierung?

Erklärung: Mit ObjectOutputStream wird ein Objekt samt allen referenzierten Objekten geschrieben, mit ObjectInputStream wieder gelesen.

Frage 2 Was muss eine Klasse tun, damit ihre Objekte serialisiert werden können?

Erklärung: Serializable hat keine Methoden – es markiert nur, dass die Klasse serialisiert werden darf. Attribute, die nicht gespeichert werden sollen, bekommen das Schlüsselwort transient.

Frage 3 Was ist der Vorteil von try-with-resources?

Erklärung: Es ersetzt den fehleranfälligen finally-Block mit close(). Exceptions müssen trotzdem behandelt oder weitergegeben werden.

Frage 4 Eine Methode zum Laden von Daten fängt eine IOException und wirft stattdessen eine eigene, fachliche Exception. Warum?

Erklärung: Ob die Daten aus einer Datei, einer Datenbank oder dem Netz kommen, ist ein Detail der Umsetzung. Die Meldung der technischen Exception wird dabei meist in die fachliche übernommen.
