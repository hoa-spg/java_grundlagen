1 — Lambda-Ausdrücke: Motivation

Der Lambda-Kalkül ist ein Konzept der theoretischen Informatik, das das Binden von Parametern an Funktionen beschreibt. In Anlehnung daran gibt es in vielen Programmiersprachen Lambda-Ausdrücke, die an bestimmten Stellen vereinfachte Funktionsaufrufe ermöglichen. In Java ist der Operator ein Pfeil -> (Bindestrich und Größer-Zeichen): links die Parameter, rechts ein Methodenrumpf (oder Methodenaufruf).

Wir betrachten ein Interface für eine binäre Operation auf ganzen Zahlen – eine Operation wie die Addition, die zwei Zahlen ein Ergebnis (wieder eine Zahl) zuordnet – und eine Klasse Calculator, die solche Berechnungen durchführt:

BinaryOperation.java Java 
public interface BinaryOperation {
    public int operation(int a, int b);
}
Calculator.java Java 
public class Calculator {

    public int calculate(BinaryOperation op, int a, int b) {
        int result = op.operation(a, b);
        System.out.println("Result of op(" + a + ", " + b + ") = " + result);
        return result;
    }
}

calculate verwendet eine konkrete BinaryOperation und wendet sie auf a und b an. Das Interface kann nicht selbst instanziiert werden – für Addition, Subtraktion usw. braucht es Klassen, die es implementieren.

2 — Drei Varianten

Variante 1: eigene Klassen

LambdaDemo.java Java 
public class LambdaDemo {

    public static void main(String[] args) {
        variantClassImplementsInterface();
        // variantAnonymousClassImplementsInterface();
        // variantWithLambdas();
    }

    public static void variantClassImplementsInterface() {
        System.out.println("Variant with Classes implementing the Interface: ");
        Calculator calc = new Calculator();
        calc.calculate(new BinaryOperationAddition(), 3, 5);
        calc.calculate(new BinaryOperationSubtraction(), 10, 4);
        calc.calculate(new BinaryOperationMultiplikation(), 2, 6);
    }
}
BinaryOperationAddition.java (die anderen analog) Java 
public class BinaryOperationAddition implements BinaryOperation {
    @Override
    public int operation(int a, int b) {
        return a + b;
    }
}

Nachteil: Obwohl jede Operation nur ein einziges Mal benötigt wird, muss eine eigene Klasse (in einer eigenen Datei) angelegt werden. Sie enthält als wesentliche Information nur die mathematische Operation, sonst viel Code ohne Aussagekraft.

Variante 2: anonyme Klassen

LambdaDemo.java Java 
public static void variantAnonymousClassImplementsInterface() {
    Calculator calc = new Calculator();
    calc.calculate(new BinaryOperation() {
                        @Override
                        public int operation(int a, int b) {
                            return a + b;
                        }
                    }, 3, 5);

    calc.calculate(new BinaryOperation() {
                        @Override
                        public int operation(int a, int b) {
                            return a - b;
                        }
                    }, 10, 4);

    calc.calculate(new BinaryOperation() {
                        @Override
                        public int operation(int a, int b) {
                            return a * b;
                        }
                    }, 2, 6);
}

Hier wird eine Instanz einer anonymen Klasse übergeben: Implizit entsteht eine neue Klasse, die BinaryOperation implementiert und nach der geschwungenen Klammer operation überschreibt. Eine eigene Datei entfällt – der Code bleibt aber unübersichtlich und redundant: Jedes Mal steht der Interfacename da, obwohl calculate ohnehin genau dieses Interface verlangt, und jedes Mal steht da, dass operation überschrieben wird, obwohl das Interface nur diese eine Methode hat.

Variante 3: Lambda-Ausdrücke

Die Motivation für Lambdas: Die ohnehin klaren Informationen muss man nicht anschreiben. Relevant ist nur, was mit a und b passiert.

LambdaDemo.java Java 
public static void variantWithLambdas() {
    Calculator calc = new Calculator();
    calc.calculate( (int a, int b) -> { return a + b; }, 3, 5 );
    calc.calculate( (a, b) -> (a - b), 10, 4);
    calc.calculate( (a, b) -> (a * b), 2, 6);
}
  • Addition: links von -> die beiden int-Parameter, rechts in geschwungenen Klammern der Methodenrumpf mit return.
  • Subtraktion und Multiplikation zeigen die Kurzform: Parametertypen weggelassen (der Compiler kennt sie aus dem Interface); bei nur einem Ausdruck entfallen auch die geschwungenen Klammern und return.
ℹ
Funktionale Interfaces

Lambdas funktionieren überall dort, wo ein Interface mit genau einer abstrakten Methode erwartet wird (funktionales Interface), z. B. Comparator, Runnable oder die Event-Listener von Benutzeroberflächen.

Rechts von -> kann auch ein Methodenaufruf stehen. Das ist bei Benutzeroberflächen sehr häufig: Lambdas behandeln Ereignisse wie den Klick auf einen Button. Der Event-Handler ist durch ein Interface spezifiziert; statt für jedes Element eine eigene Klasse zu schreiben, gibt man nur die Methode an – z. B. button.addClickListener(e -> speichern()); (Teil 4).

3 — Sortieren mit Lambdas

Um Objekte nach verschiedenen Kriterien zu sortieren, übergibt man der Sortiermethode einen Comparator – ein Interface mit der Methode int compare(T o1, T o2), die wie compareTo einen negativen Wert, 0 oder einen positiven Wert liefert. Mit Lambdas:

Sortieren mit Lambdas Java 
ArrayList<Integer> values = new ArrayList<>(
            Arrays.asList(3, 1, 5, 6, 12, 3, 5, -3, 44, 0, 1, 5));
Collections.sort(values, (a, b) -> (a - b)); // sort ascending
System.out.println("Values: " + values);

values.clear();
values.addAll(Arrays.asList(3, 1, 5, 6, 12, 3, 5, -3, 44, 0, 1, 5));
Collections.sort(values, (a, b) -> (b - a)); // sort descending
System.out.println("Values: " + values);
⚠
compare oder compareTo?

Nicht verwechseln: Comparator<T> hat die Methode compare(T o1, T o2) und vergleicht zwei fremde Objekte; Comparable<T> hat compareTo(T o) und vergleicht this mit einem anderen Objekt.

Bei Objekten mit mehreren Attributen legt man im Lambda bequem fest, wonach sortiert wird. Noch kürzer geht es mit Comparator.comparing und einer Methodenreferenz (Klasse::methode):

Personen sortieren Java 
personen.sort((a, b) -> a.getGeburtsjahr() - b.getGeburtsjahr());
personen.sort(Comparator.comparing(Person::getName));
personen.sort(Comparator.comparing(Person::getName).reversed());

4 — Lambdas in der Collection-API

Auch die Collections aus Lektion 2.7 haben Methoden, die ein Lambda erwarten. Zwei davon ersparen häufig eine ganze Schleife:

forEach und removeIf Java 
ArrayList<String> namen = new ArrayList<>(List.of("Anna", "Bert", "Alex", "Clara"));

// für jedes Element eine Aktion ausführen
namen.forEach(n -> System.out.println("Hallo " + n));

// alle Elemente entfernen, für die die Bedingung gilt
namen.removeIf(n -> n.startsWith("A"));
System.out.println(namen);   // [Bert, Clara]

removeIf ist die bequeme Alternative zum Iterator mit it.remove() (Lektion 2.7): Das Entfernen während einer for-each-Schleife führt ja zu einer ConcurrentModificationException.

Methodenreferenzen

Ruft ein Lambda nur eine einzige, bereits vorhandene Methode auf, kann man stattdessen eine Methodenreferenz mit :: schreiben. Die Parameter ergänzt der Compiler:

LambdaMethodenreferenzArt
p -> p.getName()Person::getNameMethode des übergebenen Objekts
x -> System.out.println(x)System.out::printlnMethode eines bestimmten Objekts
s -> Integer.parseInt(s)Integer::parseIntstatische Methode
Methodenreferenz statt Lambda Java 
namen.forEach(System.out::println);
personen.sort(Comparator.comparing(Person::getGeburtsjahr)
                        .thenComparing(Person::getName));

thenComparing legt ein zweites Kriterium fest, wenn das erste gleich ist – hier: bei gleichem Geburtsjahr nach dem Namen.

Projektschritt 3.5

Sortieren mit Lambdas und Methodenreferenzen

Die Firma liefert sortierte Kopien ihres Personals: absteigend nach Kosten (Lambda als Comparator) und nach Geburtsjahr (Methodenreferenz). Die Liste personal selbst bleibt unverändert.

src/main/java/Firma.java (Auszug) Java 
// Kopie, absteigend nach Kosten sortiert (Lambda als Comparator)
public List<Person> sortiertNachKosten() {
    ArrayList<Person> sortiert = new ArrayList<>(personal);
    sortiert.sort((a, b) -> b.getKostenProMonat() - a.getKostenProMonat());
    return sortiert;
}

// Kopie, nach Geburtsjahr sortiert (Methodenreferenz)
public List<Person> sortiertNachGeburtsjahr() {
    ArrayList<Person> sortiert = new ArrayList<>(personal);
    sortiert.sort(Comparator.comparing(Person::getGeburtsjahr));
    return sortiert;
}

Das Hauptprogramm gibt beide Listen aus (einmal mit for-each, einmal mit forEach und Lambda) und zeigt das Sortieren von Zahlen aus Abschnitt 3. LambdaTest prüft die Reihenfolge und dass das Original unverändert bleibt.

📁 Stand nach dieser Lektion: beispiele/3.5/

Häufige Fehler

Fehler: Lokale Variable im Lambda verändert

int summe = 0; list.forEach(p -> summe += p.getKostenProMonat()); → local variables referenced from a lambda expression must be final or effectively final.

Lambdas dürfen lokale Variablen nur lesen. Für Summen eine normale Schleife verwenden – oder einen Stream mit mapToInt(…).sum() (Lektion 3.6).

Fehler: Lambda ohne passendes Interface

Object o = (a, b) -> a + b; → incompatible types: Object is not a functional interface.

Ein Lambda braucht als Zieltyp ein funktionales Interface (genau eine abstrakte Methode), z. B. BinaryOperation oder Comparator<Person>.

Fehler: Subtraktion als Comparator bei großen Zahlen

(a, b) -> a - b sortiert falsch, wenn die Differenz den int-Bereich überschreitet (Überlauf, Lektion 1.4).

Für beliebige Werte Integer.compare(a, b) bzw. Comparator.comparing(…) verwenden.

Wissenskontrolle

Frage 1 Wofür kann ein Lambda-Ausdruck verwendet werden?

Erklärung: Ein Lambda wie (a, b) -> a.getName().compareTo(b.getName()) ersetzt eine eigene Klasse oder anonyme Klasse, die z. B. Comparator implementiert.

Frage 2 Welche Lambda-Ausdrücke sind gültige Kurzformen?

Mehrere Antworten sind richtig.

Erklärung: Bei genau einem Parameter dürfen die Klammern entfallen, bei keinem oder mehreren nicht. Besteht der Rumpf aus einem Ausdruck, entfallen geschwungene Klammern und return.

Frage 3 Was bewirkt liste.sort(Comparator.comparing(Person::getName));?

Erklärung: Comparator.comparing baut einen Comparator aus einer Methode, die den Sortierschlüssel liefert. Person::getName ist eine Methodenreferenz, kurz für p -> p.getName().

Frage 4 Was macht liste.removeIf(p -> p.getAlter() < 18);?

Erklärung: removeIf prüft jedes Element mit der Bedingung (einem Lambda) und entfernt alle Treffer direkt aus der Liste – ohne eigenen Iterator.
