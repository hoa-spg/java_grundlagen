1 — Abstrakte Methoden und abstrakte Klassen

Wird eine Klasse als abstract deklariert, kann man keine Instanzen von ihr erzeugen. Sie dient nur als mögliche Basisklasse; ihre öffentlichen Methoden stehen in allen ableitenden Klassen zur Verfügung.

Manchmal will man erzwingen, dass bestimmte Methoden von allen Unterklassen implementiert werden müssen. Dafür gibt es abstrakte Methoden: Sie haben keine Implementierung, also keinen Methodenrumpf. Sinnvoll ist das, wenn eine (abstrakte) Klasse festlegen will, dass alle konkreten Unterklassen eine bestimmte Methode anbieten, an dieser Stelle aber keine sinnvolle Implementierung möglich ist.

Person.java (Skizze) Java 
public abstract class Person {

    // Instanzvariablen

    // Konstruktoren

    // Get/Set-Methoden

    public abstract int getKostenProMonat();
}
ℹ
Regeln

Eine Klasse mit mindestens einer abstrakten Methode muss selbst abstract sein. Eine Unterklasse ist nur dann konkret (instanziierbar), wenn sie alle geerbten abstrakten Methoden implementiert – sonst muss auch sie abstract sein.

2 — Interfaces

Manchmal will man rein abstrakte Klassen definieren, die ausschließlich abstrakte Methoden (und keine Attribute) besitzen. Sie zwingen ableitende Klassen, eine bestimmte Funktionalität über eine festgelegte Schnittstelle anzubieten – deshalb heißen sie Interfaces.

Beispiel: Objekte einer Klasse sollen verglichen und sortiert werden können. Ein passendes Interface stellt die Java-Bibliothek bereit; es sieht in etwa so aus:

Comparable.java (vereinfacht) Java 
public interface Comparable<T> {

    int compareTo(T o);

}

Klassen, die dieses Interface implementieren, müssen eine konkrete Implementierung von compareTo anbieten. Statt extends verwendet man dabei das Schlüsselwort implements. Der wesentliche Unterschied zur Vererbung: Man kann nur von einer Klasse ableiten, aber eine Klasse kann mehrere Interfaces implementieren.

Person.java Java 
import java.lang.Comparable;

public abstract class Person implements Comparable<Person> {
    private String name;
    private int geburtsjahr;

    // Konstruktoren, Getter/Setter, weitere Methoden
    @Override
    public int compareTo(Person other) {
        if (other != null) {
            int c = this.getName().compareTo(other.getName());
            if (c == 0) {
                return this.getGeburtsjahr() - other.getGeburtsjahr();
            } else {
                return c;
            }
        } else {
            return Integer.MIN_VALUE; // spaeter werden wir das besser loesen
        }
    }
}

Die Methode verwendet compareTo von String – auch String implementiert Comparable<String>. Der int-Rückgabewert ist

  • kleiner als 0, wenn this vor other zu sortieren ist,
  • größer als 0, wenn es danach kommen soll,
  • 0 bei Gleichheit – dann wird hier das Geburtsjahr für einen genaueren Vergleich herangezogen; die Differenz der beiden int-Werte verhält sich genauso.
💡
import java.lang
import java.lang.Comparable; ist erlaubt, aber überflüssig – java.lang ist immer importiert.

3 — Klassenhierarchien

Angenommen, auch ein Freelancer soll zum Personal gehören. Auch er hat Name und Geburtsjahr, aber keinen festen Stundenlohn und keine fixe Wochenstundenanzahl: Er arbeitet auf Projektbasis und bekommt eine Projektpauschale. Die Lösung ist eine mehrstufige Vererbungshierarchie: Gemeinsamer Basistyp von Freelancer und Mitarbeiter wird Person (Name, Geburtsjahr). Stundenlohn und Wochenstunden – gemeinsam für Arbeiter und Angestellte – liegen in Mitarbeiter, das von Person ableitet.

Person.java Java 
public abstract class Person implements Comparable<Person> {

    private String name;
    private int geburtsjahr;

    public Person() {
        setName("n/a");
        setGeburtsjahr(1900);
    }

    public Person(String name, int geburtsjahr) {
        setName(name);
        setGeburtsjahr(geburtsjahr);
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        } else {
            System.out.println("Fehler: ungueltiger Name: " + name);
        }
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }

    public void setGeburtsjahr(int geburtsjahr) {
        if (geburtsjahr >= 1900 && geburtsjahr <= 2050) {
            this.geburtsjahr = geburtsjahr;
        } else {
            System.out.println("Fehler: ungueltiges Geburtsjahr: " + geburtsjahr);
        }
    }

    public abstract int getKostenProMonat();

    @Override
    public int compareTo(Person o) {
        if (o != null) {
            int c = this.getName().compareTo(o.getName());
            if (c == 0) {
                return this.getGeburtsjahr() - o.getGeburtsjahr();
            } else {
                return c;
            }
        } else {
            return -1; // spaeter werden wir das besser loesen
        }
    }

    @Override
    public String toString() {
        String str = getName() + " (Geb.Jahr: " + getGeburtsjahr() + ")";
        return str;
    }
}

Person enthält die abstrakte Methode zur Berechnung der monatlichen Kosten: Einerseits sollen alle konkreten Unterklassen sie implementieren müssen, andererseits fehlen hier die nötigen Attribute (Stundenlohn, Projektpauschale) für eine sinnvolle Implementierung. compareTo aus Comparable<Person> steht allen Unterklassen zur Verfügung; der Typparameter ist Person, da mit Personen bzw. deren Untertypen verglichen wird.

    // Get-/Set-Methoden fuer stundenlohn und anzahlWochenStunden
    // mit den Pruefungen aus Lektion 2.8

    @Override

        // eigentlich 4.35 Wochen pro Monat
        // hier der Einfachkeit halber * 4
        int kosten = 4 * getStundenlohn() * getAnzahlWochenStunden();
        return kosten;
    }

    @Override
    public String toString() {
        String str = super.toString();
        str += " Stundenlohn: " + getStundenlohn() + ", "
               + getAnzahlWochenStunden() + " h/W";
        return str;
    }

    public void print() {
        System.out.println(this);
    }
}

Die Firma verwaltet jetzt ArrayList<Person>, berechnet die Gesamtkosten und kann sortieren:

Firma.java Java 
import java.util.ArrayList;
import java.util.Collections;

public class Firma {

    private String name;
    private ArrayList<Person> personal;

    public Firma() {
        personal = new ArrayList<>();
        setName("Default GmbH");
    }

    public Firma(String name) {
        personal = new ArrayList<>();
        setName(name);
    }

    // getName, setName wie bisher

    public void einstellen(Person m) {
        if (m != null) {
            personal.add(m);
        } else {
            System.out.println("Fehler: ungueltiger Mitarbeiter: " + m);
        }
    }

    public boolean kuendigen(Person m) {
        if (m != null) {
            return personal.remove(m);
        } else {
            System.out.println("Fehler: ungueltiger Mitarbeiter: " + m);
        }
        return false;
    }

    public String toString() {
        String str = "Firma: " + getName()
                     + "\n-----------------------------------------\n";

        for (Person m : personal) {
            str += m + "\n";
        }
        str += "\n";

        int kosten = 0;
        for (Person m : personal) {
            kosten += m.getKostenProMonat();
        }
        str += "Kosten pro Monat: " + kosten + "\n";
        str += "-----------------------------------------\n";

        return str;
    }

    public void print() {
        System.out.println(this);
    }

    public void sortieren() {
        Collections.sort(personal);
    }
}

sortieren verwendet die statische Methode sort der Klasse Collections. Sie funktioniert nur mit Collections von Klassen, die das Comparable-Interface implementieren: So erfährt der Sortieralgorithmus, wie zwei Objekte dieser Klasse (oder ihrer Unterklassen) in die richtige Reihenfolge zu bringen sind. Die Kostenberechnung ruft für jede Person getKostenProMonat() auf – für Freelancer, Arbeiter, Angestellte und Praktikanten jeweils die passende Implementierung.

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Abstrakte Klasse instanziiert

new Person("Anna", 1990) → Person is abstract; cannot be instantiated.

Nur konkrete Unterklassen können erzeugt werden: Person p = new Freelancer(…); – die Variable darf den abstrakten Typ haben.

Fehler: Abstrakte Methode nicht implementiert

Freelancer is not abstract and does not override abstract method getKostenProMonat() in Person.

Die Methode mit gleicher Signatur in der Unterklasse implementieren (Alt+Enter → Implement methods) oder die Unterklasse ebenfalls abstract machen.

Fehler: Collections.sort übersetzt nicht

no suitable method found for sort(ArrayList<Person>).

Die Elementklasse muss Comparable<Person> implementieren (mit Typparameter!) und compareTo(Person o) anbieten.

Frage 1 Was gilt für eine abstrakte Klasse?

Mehrere Antworten sind richtig.

Erklärung: Eine abstrakte Klasse ist ein unvollständiger Bauplan: gemeinsame Attribute und Methoden plus Methoden, die erst die Unterklassen konkret umsetzen.

Frage 2 Wie viele Basisklassen und wie viele Interfaces kann eine Java-Klasse haben?

Erklärung: Java erlaubt keine Mehrfachvererbung von Klassen. Interfaces beschreiben nur, was eine Klasse können muss, deshalb darf eine Klasse mehrere davon implementieren.

Frage 3 Welche Methode muss eine Klasse implementieren, die Comparable<Person> implementiert?

Erklärung: compareTo legt die natürliche Reihenfolge fest. Danach kann Collections.sort(liste) die Liste sortieren.

Frage 4 Was ist ein Interface?

Erklärung: Ein Interface ist ein Vertrag. Jede Klasse, die es implementiert, garantiert die Methoden – so kann man Objekte verschiedener Klassen einheitlich verwenden.
