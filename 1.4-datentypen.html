1 — Variablen und Datentypen

Bisher wurden die Datentypen String und int bei Objekteigenschaften und Parametern verwendet. Der Oberbegriff dafür lautet Variablen; eine weitere Art, die lokalen Variablen, folgt in Lektion 1.6. Der Datentyp legt fest, welche Art von Werten eine Variable aufnehmen kann. Zeichenketten stehen stets in doppelten Anführungszeichen, z. B. "Max Maier"; auch die leere Zeichenkette "" ist möglich.

2 — Primitive Datentypen

Die primitiven (im Sinne von einfachen, grundlegenden) Datentypen sind in Java „fest eingebaut“: byte, short, int, long, float, double, boolean und char.

Je größer der darstellbare Zahlenbereich, desto mehr Platz im Hauptspeicher wird benötigt. Derartige Überlegungen spielen vorerst nur eine untergeordnete Rolle.

Typkonvertierung: automatisch oder mit Cast

Oft passt der Typ eines Werts nicht genau zum Typ der Variablen, in die er gespeichert werden soll, z. B. eine ganze Zahl in einer double-Variablen. Java unterscheidet dann zwei Fälle:

  • Erweiternde Konvertierung (in einen „größeren“ Typ): passiert automatisch (implizit), weil der Wert sicher hineinpasst.
  • Einschränkende Konvertierung (in einen „kleineren“ Typ): Dabei kann etwas verloren gehen. Der Compiler verlangt deshalb einen Cast: den Zieltyp in runden Klammern vor dem Wert, z. B. (int) 3.99. Damit bestätigst du ausdrücklich, dass du einen möglichen Verlust in Kauf nimmst.

Die erweiternde Richtung lässt sich als Kette darstellen:

byte → short → int → long → float → double
char → int

In Pfeilrichtung konvertiert Java automatisch, auch über mehrere Schritte (int → double). Gegen die Pfeilrichtung ist ein Cast nötig. boolean lässt sich weder in einen anderen primitiven Typ umwandeln noch aus einem erzeugen – auch nicht mit Cast.

Wo automatisch konvertiert wird

  • bei der Zuweisung: double d = 5; speichert 5.0
  • bei der Parameterübergabe: Eine Methode setPreis(double preis) kann mit setPreis(20) aufgerufen werden
  • beim Rückgabewert: Eine Methode mit Rückgabetyp double darf return anzahl; mit einem int schreiben
  • in Rechenausdrücken mit gemischten Typen: Ist ein Operand double, wird der andere zu double und das Ergebnis ist double (sonst float, sonst long). byte, short und char werden beim Rechnen immer mindestens zu int.
Erweiternde Konvertierung (automatisch) Java 
int anzahl = 7;
double d = anzahl;          // 7.0
long l = anzahl;            // 7
double summe = anzahl + 0.5; // 7.5 – anzahl wird für die Rechnung zu double

char c = 'A';
int code = c;               // 65 – jedes Zeichen hat einen Zahlencode (Unicode)
int naechster = c + 1;      // 66 – char + int ergibt int

byte b1 = 10;
byte b2 = 20;
int s = b1 + b2;            // byte + byte ergibt int!
// byte s = b1 + b2;        // Fehler: possible lossy conversion from int to byte

Erweiternd heißt nicht immer verlustfrei

Ein float bzw. double hat zwar einen viel größeren Zahlenbereich als int bzw. long, speichert aber nur eine begrenzte Anzahl gültiger Stellen (float etwa 7, double etwa 15–16). Bei großen Ganzzahlen gehen deshalb die hinteren Stellen verloren – obwohl Java ohne Cast konvertiert:

Genauigkeitsverlust trotz automatischer Konvertierung Java 
int i = 123456789;
float f = i;
System.out.println(f);        // 1.23456792E8 – die letzten Stellen stimmen nicht mehr

long l = 123456789012345678L;
double d = l;
System.out.println((long) d); // 123456789012345680

Die Konvertierungen byte/short/char → int → long und int/float → double sind dagegen immer exakt.

Wo ein Cast notwendig ist und was dabei passiert

KonvertierungBeispielErgebnisWas passiert
double → int(int) 3.99
(int) -3.99		3
-3		Nachkommastellen werden abgeschnitten, nicht gerundet
double → float(float) 0.12345678910.12345679Genauigkeit geht verloren
long → int(int) 3000000000L-1294967296Wert passt nicht → die oberen Bits fallen weg, es entsteht eine völlig andere Zahl
int → byte(byte) 200-56wie oben: byte reicht nur von -128 bis 127
int → char(char) 66'B'Zahlencode wird als Zeichen interpretiert
char → short/byte(byte) 'A'65char hat keine negativen Werte, deshalb auch hier Cast

Zum Runden statt Abschneiden gibt es Math.round(3.5) (ergibt 4, als long). Wichtig: Ein Cast prüft nichts. Passt der Wert nicht in den Zieltyp, gibt es keine Fehlermeldung, sondern einfach ein falsches Ergebnis.

Einschränkende Konvertierung (Cast nötig) Java 
double preis = 19.99;
// int euro = preis;              // Fehler: possible lossy conversion from double to int
int euro = (int) preis;           // 19
long gerundet = Math.round(preis); // 20

int code = 66;
char zeichen = (char) code;       // 'B'
char ziffer = '7';
int wert = ziffer - '0';          // 7 – Ziffernzeichen in Zahl umrechnen

Literale haben auch einen Typ

  • Ganzzahlige Literale wie 42 sind int, Kommazahlen wie 3.5 sind double. Deshalb übersetzt float f = 3.5; nicht – richtig ist float f = 3.5f;. Für long-Werte über dem int-Bereich braucht es ein L: long l = 3000000000L;
  • Ausnahme: Ein konstanter int-Wert, der in den Zieltyp passt, darf ohne Cast in byte, short oder char gespeichert werden: byte b = 10; und char c = 65; (ergibt 'A') sind erlaubt, byte b = 200; nicht.
  • Bei zusammengesetzten Zuweisungen wie += castet Java stillschweigend: int x = 5; x += 2.7; übersetzt und ergibt 7, obwohl x = x + 2.7; einen Fehler liefert.
⚠
Überlauf ohne Fehlermeldung

Auch ohne Cast kann ein Ergebnis zu groß werden: 2_000_000_000 * 2 ergibt -294967296, weil beide Operanden int sind und das Ergebnis den int-Bereich überschreitet. Abhilfe: einen Operanden zu long machen (2_000_000_000L * 2). Dasselbe Prinzip steckt hinter der ganzzahligen Division 181 / 100 = 1, die dir in Lektion 1.6 begegnet.

3 — Referenzdatentypen

Mit der Klasse Student haben wir einen eigenen Datentyp erstellt! Alle Klassen definieren einen Datentyp – im Gegensatz zu den primitiven Typen handelt es sich um Referenzdatentypen. Auch String ist ein Referenzdatentyp, also eine Klasse aus der Java-Bibliothek. Referenzdatentypen beginnen laut Konvention stets mit einem Großbuchstaben!

Der wesentliche Unterschied: Eine Variable eines Referenzdatentyps enthält nicht den eigentlichen Wert, sondern eine Referenz (einen Verweis) auf den Speicherort, an dem die Daten tatsächlich liegen. Daraus ergeben sich zwei Konsequenzen:

  • Der Verweis kann „ins Leere“ gehen. Der Wert der Objektreferenz ist dann null. Ist eine Objektreferenz null, so können darauf keine Methoden aufgerufen werden – das führt zu einem Laufzeitfehler, also einem Absturz des Programms (NullPointerException).
  • Auf ein und dasselbe Objekt können mehrere Referenzen verweisen: Die Variable stud1 kann auf denselben Studenten verweisen wie stud2.
Zwei Referenzen, ein Objekt Java 
Student stud1 = new Student("Peter", 1981);
Student stud2 = stud1;          // keine Kopie! stud2 zeigt auf dasselbe Objekt
stud2.setName("Pedro");
System.out.println(stud1.getName());   // Pedro

Student stud3 = null;           // verweist auf nichts
stud3.getName();                // Laufzeitfehler: NullPointerException

Projektschritt

Projektschritt 1.4

Stundenlohn und Wochenstunden

Ein Mitarbeiter verdient einen stundenlohn (in Euro) für eine bestimmte anzahlWochenStunden. Beides sind ganze Zahlen, also int. Die beiden Konstruktoren setzen Standardwerte (10 Euro, 40 Stunden), dazu kommen Get-/Set-Methoden, und print() gibt die neuen Werte mit aus.

src/main/java/Mitarbeiter.java (Auszug) Java 
private int stundenlohn;          // in Euro
private int anzahlWochenStunden;

public Mitarbeiter(String name, int geburtsjahr) {
    setName(name);
    setGeburtsjahr(geburtsjahr);
    setStundenlohn(10);
    setAnzahlWochenStunden(40);
}

public int getStundenlohn() {
    return stundenlohn;
}

public void setStundenlohn(int stundenlohn) {
    this.stundenlohn = stundenlohn;
}

public void print() {
    System.out.println("Mitarbeiter: " + name + " (Geburtsjahr: " + geburtsjahr
                       + "), " + stundenlohn + " Euro/h, "
                       + anzahlWochenStunden + " h/Woche");
}

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Methode auf null aufgerufen

Das Programm bricht mit NullPointerException ab, z. B. bei student.getName().

Die Referenz verweist auf kein Objekt. Vor dem Aufruf mit new ein Objekt erzeugen bzw. mit if (student != null) prüfen (Lektion 1.6).

Fehler: possible lossy conversion

int euro = 19.99; oder float f = 3.5; → incompatible types: possible lossy conversion from double to int (bzw. to float).

Einschränkende Konvertierungen brauchen einen Cast: (int) 19.99 schneidet ab (19), Math.round(19.99) rundet. Bei float-Literalen ein f anhängen: 3.5f.

Fehler: Referenz kopiert statt Objekt

Nach Student s2 = s1; s2.setName("X"); hat auch s1 plötzlich den Namen „X“.

= kopiert bei Objekten nur den Verweis. Für ein zweites, unabhängiges Objekt braucht es ein neues new Student(…).

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Welcher Datentyp passt für eine Kommazahl wie 19.99, wenn nichts anderes verlangt ist?

Erklärung: double ist der Standardtyp für Kommazahlen; Literale wie 19.99 sind automatisch double. int speichert nur ganze Zahlen.

Frage 2 Welche Zeile übersetzt nicht ohne Cast?

Erklärung: Von double nach int geht Information verloren (die Nachkommastellen), daher verlangt Java einen ausdrücklichen Cast: int i = (int) 7.9; ergibt 7. Erweiternde Konvertierungen wie int → double passieren automatisch.

Frage 3 Welche Typen sind primitive Datentypen?

Mehrere Antworten sind richtig.

Erklärung: Java hat acht primitive Typen (byte, short, int, long, float, double, char, boolean), alle klein geschrieben. String ist eine Klasse und damit ein Referenzdatentyp.

Frage 4 Was bedeutet Kunde k = null;?

Erklärung: null heißt: kein Verweis. Ruft man darauf eine Methode auf, bricht das Programm mit einer NullPointerException ab.
