1 — Konstruktoren

Der Konstruktor legt fest, wie ein Objekt erzeugt wird – also welche Werte den Eigenschaften dabei zugewiesen werden. Er heißt genau wie die Klasse und hat keinen Rückgabetyp. Im parameterlosen Konstruktor verwenden wir die Set-Methoden, um für alle Eigenschaften Default-Werte zu setzen:

Student.java Java 
public class Student {

    private String name;
    private int geburtsjahr;

    public Student() {
        setName("n/a");
        setGeburtsjahr(1970);
    }

    // die Get-/Set-Methoden sind hier der Uebersicht halber weggelassen
}

Konstruktoren können wie Set-Methoden Parameter haben; mehrere Parameter werden durch Beistriche getrennt. Der zweite Konstruktor ist eine alternative Möglichkeit, ein Student-Objekt zu erzeugen – die übergebenen Werte werden an die Set-Methoden weitergereicht:

Student.java Java 
public class Student {

    private String name;
    private int geburtsjahr;

    public Student() {
        setName("n/a");
        setGeburtsjahr(1970);
    }

    public Student(String name, int geburtsjahr) {
        setName(name);
        setGeburtsjahr(geburtsjahr);
    }

    // die Get-/Set-Methoden sind hier der Uebersicht halber weggelassen
}
Objekte erzeugen (z. B. in einer Testklasse) Java 
Student s1 = new Student();                 // Name "n/a", Geburtsjahr 1970
Student s2 = new Student("Sandra", 1985);   // Name "Sandra", Geburtsjahr 1985
💡
Warum die Set-Methoden aufrufen?

Ruft der Konstruktor die Set-Methoden auf, gelten die Prüfungen der Set-Methoden (Lektion 1.6) automatisch auch beim Erzeugen. Die Logik steht nur an einer Stelle.

2 — Das Schlüsselwort this

In setName hieß der Parameter bisher neuerName. Wählt man stattdessen name (die Bezeichnung ist frei wählbar), ergibt sich ein Problem:

✗ DON'T

So nicht Java 
public class Student {
    private String name;

    public void setName(String name) {
        name = name; // !?
    }
}

✓ DO

Richtig Java 
public class Student {
    private String name;

    public void setName(String name) {
        this.name = name; // this.name = Objekteigenschaft
    }
}

In name = name; ist unklar, welcher name gemeint ist: die Objekteigenschaft oder der Parameter? Es liegt ein Namenskonflikt vor. Java nimmt in beiden Fällen den Parameter – die Eigenschaft bleibt unverändert. Das Schlüsselwort this gibt an, dass die Eigenschaft dieses Objekts gemeint ist.

ℹ
Wann this?

Bei Uneindeutigkeiten muss this verwendet werden, anderenfalls kann man es verwenden (muss aber nicht).

3 — Methoden

Methoden sind Bestandteile von Klassen, die bestimmte Aufgaben durchführen: Werte ändern, Berechnungen durchführen usw. Get- und Set-Methoden kennst du bereits, auch Konstruktoren sind spezielle Methoden.

TeilIm Beispiel public int alterBerechnen(int aktuellesJahr)
Zugriffs-Modifierpublic
Rückgabetypint – der Aufrufer erhält eine ganze Zahl
MethodennamealterBerechnen
Parameterint aktuellesJahr
Methodenrumpfder Code in den geschwungenen Klammern

Modifier, Rückgabetyp, Name und Parameter bilden zusammen den Methodenkopf.

Student.java Java 
public class Student {

    private String name;
    private int geburtsjahr;

    public int alterBerechnen(int aktuellesJahr) {
        return aktuellesJahr - this.geburtsjahr; // Anmerkung: this kann hier weggelassen werden!
    }
}

Das Alter ergibt sich aus der Differenz von aktuellesJahr und geburtsjahr. Das Schlüsselwort return gibt den Rückgabewert zurück. Meist steht return am Ende einer Methode, grundsätzlich sind aber auch Return-Statements an anderen Stellen möglich.

4 — Ausgabe: die Print-Methode

Mit System.out.println („Print-Line“) machst du Ausgaben auf die Konsole. Zur Ausgabe von Objekten schreiben wir eigene Methoden, die den Inhalt des Objekts ausgeben:

Student.java Java 
public class Student {

    private String name;
    private int geburtsjahr;

    // Konstruktoren hier ausgelassen

    // Get-/Set-Methoden hier ausgelassen

    public void printStudent() {
        System.out.println("Name: " + name + " (Geburtsjahr: " + geburtsjahr + ")");
    }
}
  • Strings stehen in doppelten Anführungszeichen und werden genau so ausgegeben.
  • Der Operator + verkettet Strings.
  • geburtsjahr ist eine Zahl (int) – Java wandelt sie bei der Verkettung automatisch in einen String um.
Konsole (für Sandra, 1985) Text 
Name: Sandra (Geburtsjahr: 1985)

5 — Konventionen

Einige Konventionen erzwingt der Compiler nicht, sie sind aber unbedingt einzuhalten:

  • Klassennamen beginnen mit einem Großbuchstaben, Methoden- und Eigenschaftsnamen mit einem Kleinbuchstaben.
  • Zusammengesetzte Wörter in camelCase: getName statt getname, alterBerechnen.
  • Alles nach einer öffnenden { wird eingerückt; die Einrückung endet mit der schließenden }.
  • Konsistente Leerzeichen: getName() { statt getName(){.

Für die Position der öffnenden Klammer gibt es zwei verbreitete Stile:

Stil „1TBS“ Java 
public class Student {
    private String name;
    private int geburtsjahr;

    public String getName() {
        return name;
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }
}
Stil „Allman“ Java 
public class Student
{
    private String name;
    private int geburtsjahr;

    public String getName()
    {
        return name;
    }

    public int getGeburtsjahr()
    {
        return geburtsjahr;
    }
}

Beim Allman-Stil steht jede öffnende Klammer in einer eigenen Zeile, genau über der schließenden – die Struktur ist gut erkennbar, es entstehen aber viele zusätzliche Zeilen. Die Mehrheit der Java-Programmierer bevorzugt deshalb 1TBS (One True Brace Style): Die öffnende Klammer steht immer am Ende der Zeile, und auch einzeilige if-Blöcke bekommen Klammern. Entscheide dich für einen Stil und verwende ihn konsistent!

ℹ
Und K&R?

Der Name kommt von Kernighan und Ritchie, den Autoren des klassischen C-Buchs. Im K&R-Stil steht die öffnende Klammer bei Methoden (in C: Funktionen) in einer eigenen Zeile, bei if, while usw. dagegen am Zeilenende. 1TBS ist eine Variante davon, die die Klammer überall ans Zeilenende setzt.

Projektschritt 1.3

Konstruktoren, this und erste Methoden

Der Mitarbeiter bekommt zwei Konstruktoren, Set-Methoden mit this, die Berechnung des Alters und eine Print-Methode. Erzeuge einen Mitarbeiter mit new Mitarbeiter("Karl Maier", 1989) und rufe alterBerechnen(2026) und print() auf.

src/main/java/Mitarbeiter.java Java 
/*
  Personalverwaltung – die Klasse Mitarbeiter modelliert eine Person,
  die in einer Firma arbeitet.
  Stand: Lektion 1.3 (Konstruktoren, this, Methoden)
*/
public class Mitarbeiter {

    // Objekteigenschaften (Attribute)
    private String name;
    private int geburtsjahr;

    // Konstruktoren
    public Mitarbeiter() {
        setName("n/a");
        setGeburtsjahr(1970);
    }

    public Mitarbeiter(String name, int geburtsjahr) {
        setName(name);
        setGeburtsjahr(geburtsjahr);
    }

    // Get-/Set-Methoden
    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }

    public void setGeburtsjahr(int geburtsjahr) {
        this.geburtsjahr = geburtsjahr;
    }

    // Weitere Methoden
    public int alterBerechnen(int aktuellesJahr) {
        return aktuellesJahr - geburtsjahr;
    }

    public void print() {
        System.out.println("Mitarbeiter: " + name + " (Geburtsjahr: " + geburtsjahr + ")");
    }
}

Fehler: Konstruktor mit Rückgabetyp

public void Student() { … } übersetzt zwar, wird aber beim new nicht aufgerufen – die Eigenschaften bleiben null bzw. 0.

Ein Konstruktor hat keinen Rückgabetyp, auch nicht void: public Student() { … }.

Fehler: this vergessen

public void setName(String name) { name = name; } – der Name bleibt nach dem Aufruf unverändert.

this.name = name; – links die Eigenschaft des Objekts, rechts der Parameter.

Fehler: Ausgabe statt Rückgabe

Eine Methode alterBerechnen schreibt das Ergebnis nur mit println auf die Konsole; andere Methoden können damit nicht weiterrechnen.

Berechnungen mit return zurückgeben. Die Ausgabe übernimmt der Aufrufer bzw. eine eigene Print-Methode.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was ist ein Konstruktor?

Erklärung: Der Konstruktor heißt genau wie die Klasse, hat keinen Rückgabetyp (auch nicht void) und setzt die Anfangswerte des neuen Objekts.

Frage 2 Ein Konstruktorparameter heißt genauso wie ein Attribut, im Rumpf steht nur name = name;. Was passiert?

Erklärung: Der Parameter verdeckt das gleichnamige Attribut. Mit this.name = name; sagt man ausdrücklich: das Attribut dieses Objekts bekommt den Wert des Parameters.

Frage 3 Eine Methode hat den Rückgabetyp int. Was muss in ihrem Rumpf stehen?

Erklärung: Der Rückgabetyp verspricht dem Aufrufer einen Wert. Ohne return meldet der Compiler missing return statement. Eine Ausgabe auf der Konsole ist etwas anderes als eine Rückgabe.

Frage 4 Welche Namen entsprechen den Java-Konventionen?

Erklärung: Klassen beginnen mit einem Großbuchstaben, Methoden und Variablen mit einem Kleinbuchstaben; zusammengesetzte Wörter werden in camelCase geschrieben. Bindestriche sind in Namen gar nicht erlaubt.
