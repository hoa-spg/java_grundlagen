1 — Vererbung: die Idee

Die Vererbung ist ein zentrales Konzept der objektorientierten Programmierung: Klassen werden in hierarchische Beziehungen gestellt. Leitet eine Klasse von einer anderen ab, heißt die ableitende Klasse Unterklasse (Subklasse), die andere Basisklasse (Oberklasse). Öffentliche Methoden der Basisklasse sind in der Unterklasse automatisch vorhanden und können bei ihren Objekten verwendet werden, auch wenn sie dort nicht im Code stehen.

Vererbung wird oft eingesetzt, um speziellere Varianten von Klassen zu erzeugen, ohne den Code der Basisklasse neu zu implementieren. Unterklassen können überall dort verwendet werden, wo ihre Basisklasse erwartet wird – z. B. bei Parametern oder in Collections.

Beispiel: Das Personal einer Firma besteht aus Arbeitern und Angestellten. Gemeinsam haben sie name: String, geburtsjahr: int, stundenlohn: int und anzahlWochenStunden: int. Ein Arbeiter kann facharbeiter: boolean sein, ein Angestellter eine ueberstundenPauschale: boolean haben. Viele Gemeinsamkeiten – aber auch Unterschiede.

            str += " Facharbeiter";

Man sieht: Der Code ist in weiten Teilen nahezu ident. Alle Änderungen müssten in beiden Klassen konsistent durchgeführt werden – aufwändig und fehleranfällig. Duplizierter Code ist oft ein Anzeichen für schlechtes Design. (Und prompt ist es auch hier passiert: Die Kostenmethode heißt einmal getKostenProMonat, einmal getKosten.)

Die monatlichen Kosten: Bei Mitarbeitern ohne Überstundenpauschale werden fünf zusätzliche Stunden kalkuliert, bei Facharbeitern ein Zuschlag von 200 Euro. Beide Berechnungen erheben keinen Anspruch auf buchhalterische Korrektheit, sie sollen nur die beiden Klassen unterscheiden.

ℹ
Der ternäre Operator

In toString von Arbeiter verhält sich die vorletzte Zeile genau wie das darüber auskommentierte if/else: bedingung ? wertWennTrue : wertWennFalse liefert je nach Bedingung einen der beiden Werte. Praktisch für kurze Fallunterscheidungen in Ausdrücken.

Noch ein Problem: Eine Firma soll Arbeiter und Angestellte verwalten. Ohne Vererbung bräuchte man zwei Listen, ArrayList<Arbeiter> und ArrayList<Angestellter>, und die gesamte Logik zum Einstellen oder Kündigen doppelt. Tatsächlich sind beide nur verschiedene Ausprägungen von Mitarbeitern und sollten in einer Collection verwaltet werden – ohne Vererbung unmöglich, da es zwei völlig unabhängige Typen sind.

3 — Die Lösung: extends und super

Zuerst wird eine Klasse Mitarbeiter mit allen gemeinsamen Attributen definiert. Von ihr leiten Angestellter und Arbeiter mit dem Schlüsselwort extends ab.

Mitarbeiter.java Java 
public class Mitarbeiter {

    private String name;
    private int geburtsjahr;
    private int stundenlohn;
    private int anzahlWochenStunden;

    public Mitarbeiter() {
        setName("n/a");
        setGeburtsjahr(1900);
        setStundenlohn(10);
        setAnzahlWochenStunden(40);
    }

    public Mitarbeiter(String name, int geburtsjahr, int stundenlohn,
                       int anzahlWochenStunden)
    {
        setName(name);
        setGeburtsjahr(geburtsjahr);
        setStundenlohn(stundenlohn);
        setAnzahlWochenStunden(anzahlWochenStunden);
    }

    // Get-/Set-Methoden fuer name, geburtsjahr, stundenlohn und
    // anzahlWochenStunden mit den Pruefungen wie oben

    public int getKostenProMonat() {
        // eigentlich 4.35 Wochen pro Monat
        // hier der Einfachkeit halber * 4
        int kosten = 4 * getStundenlohn() * getAnzahlWochenStunden();
        return kosten;
    }

    @Override
    public String toString() {
        String str = getName() + " (Geb.Jahr: " + getGeburtsjahr() + ")";
        str += " Stundenlohn: " + getStundenlohn() + ", "
               + getAnzahlWochenStunden() + " h/W";
        return str;
    }

    public void print() {
        System.out.println(this);
    }
}

Diese Klasse ist die Basis für Angestellter und Arbeiter, die mit Vererbung wesentlich kompakter ausfallen:

public class Angestellter extends Mitarbeiter {

    private boolean ueberstundenPauschale;

    public Angestellter(String name, int geburtsjahr,

    }

               : " (keine Uestd.-Pauschale)";
        return str;
    }
}

  • extends Mitarbeiter gibt an, dass die Klasse von Mitarbeiter ableitet.
  • In der ersten Zeile der Konstruktoren steht super(…): der Aufruf des Konstruktors der Basisklasse mit Parametern oder Defaultwerten. Zusätzliche Attribute werden wie bisher mit Set-Methoden initialisiert. Der Aufruf von super(…) muss in der ersten Zeile stehen.
  • Getter/Setter gibt es nur für das neue Attribut. Alle öffentlichen (konkret public und protected) Methoden der Basisklasse sind durch die Vererbung automatisch vorhanden, z. B. getName() oder getGeburtsjahr().
  • Die private Attribute der Basisklasse werden zwar mitvererbt, sind in der Unterklasse aber nicht direkt sichtbar – Zugriff nur über die Get-/Set-Methoden.

4 — Überschreiben von Methoden

Entspricht eine Methode der Basisklasse nicht dem gewünschten Verhalten der Unterklasse, kann sie überschrieben werden – sie wird durch eine speziellere Variante ersetzt. Wird getKostenProMonat auf einem Arbeiter aufgerufen, so wird immer dessen Methode verwendet.

Mit der Annotation @Override wird dem Compiler genau diese Absicht mitgeteilt. Sie ist nicht zwingend, aber der Compiler meldet dann einen Fehler, falls tatsächlich keine Methode überschrieben wird (z. B. wegen eines Tippfehlers). Sie sollte daher immer verwendet werden.

Mit super.getKostenProMonat() wird die überschriebene Methode der Basisklasse aufgerufen. Sie liefert schon die Grundfunktionalität und soll deshalb verwendet werden (Prinzip: Code-Wiederverwendung); die folgenden Zeilen spezialisieren sie für den Arbeiter.

5 — Polymorphismus

Polymorphismus (Vielgestaltigkeit) bezeichnet u. a. die Eigenschaft, dass Objekte von Unterklassen überall dort verwendet werden können, wo die Basisklasse erwartet wird. Die Firma verwaltet Arbeiter und Angestellte in einer Liste:

Firma.java Code anzeigen (63 Zeilen)
Firma.java Java 
import java.util.ArrayList;

public class Firma {

    private String name;

    private ArrayList<Mitarbeiter> personal;

    public Firma() {
        personal = new ArrayList<>();
        setName("Default GmbH");
    }

    public Firma(String name) {
        personal = new ArrayList<>();
        setName(name);
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        } else {
            System.out.println("Fehler: ungueltiger Name: " + name);
        }
    }

    public void einstellen(Mitarbeiter m) {
        if (m != null) {
            personal.add(m);
        } else {
            System.out.println("Fehler: ungueltiger Mitarbeiter: " + m);
        }
    }

    public boolean kuendigen(Mitarbeiter m) {
        if (m != null) {
            return personal.remove(m);
        } else {
            System.out.println("Fehler: ungueltiger Mitarbeiter: " + m);
        }
        return false;
    }

    @Override
    public String toString() {
        String str = "Firma: " + getName()
                     + "\n-----------------------------------------\n";

        for (Mitarbeiter m : personal) {
            str += m + "\n";
        }
        str += "-----------------------------------------\n";
        return str;
    }

    public void print() {
        System.out.println(this);
    }
}

ArrayList<Mitarbeiter> personal kann sowohl Arbeiter als auch Angestellte aufnehmen: Beide haben alle Eigenschaften und Fähigkeiten eines Mitarbeiters und können daher auch in dessen „Gestalt“ erscheinen – ihr Typ ist polymorph. Dasselbe gilt für Parameter: einstellen(Mitarbeiter m) akzeptiert Objekte aller Unterklassen.

Polymorphismus in Aktion Java 
Firma firma = new Firma("Spengergasse OG");
firma.einstellen(new Arbeiter("Karl", 1989, 15, 40, true));
firma.einstellen(new Angestellter("Susanne", 1991, 20, 30, false));

Mitarbeiter m = new Arbeiter("Sepp", 1981, 18, 38, false);
System.out.println(m.getKostenProMonat());  // ruft Arbeiter.getKostenProMonat auf
// m.isFacharbeiter();  // Fehler: der Typ der Variablen ist Mitarbeiter
💡
Dynamische Bindung

Welche überschriebene Methode läuft, entscheidet das tatsächliche Objekt, nicht der Typ der Variablen. Welche Methoden man aufrufen darf, entscheidet dagegen der Typ der Variablen.

Bei toString in Firma steht ebenfalls @Override. Welche Methode wird hier überschrieben? Sie stammt aus der Klasse Object, von der alle Klassen implizit ableiten. Object implementiert einige wenige Methoden, die die Basisfunktionalität aller Objekte bilden (toString, equals, hashCode, …); einige davon werden oft überschrieben.

Angestellte und Arbeiter

  Personalverwaltung – ein Arbeiter ist ein Mitarbeiter (extends),
  Facharbeiter erhalten einen Zuschlag.
  Stand: Lektion 2.8 (Vererbung)
*/
public class Arbeiter extends Mitarbeiter {

    private boolean facharbeiter;

    public Arbeiter() {
        super("n/a", 1970, 10, 40);
        setFacharbeiter(false);
    }

                    int anzahlWochenStunden, boolean facharbeiter)
    {
        super(name, geburtsjahr, stundenlohn, anzahlWochenStunden);
        setFacharbeiter(facharbeiter);
    }

    public boolean isFacharbeiter() {
        return facharbeiter;
    }

    public void setFacharbeiter(boolean facharbeiter) {
        this.facharbeiter = facharbeiter;
    }

    @Override
    public int getKostenProMonat() {
        int kosten = super.getKostenProMonat();
        if (isFacharbeiter()) {
            kosten += 200; // Facharbeiterzuschlag
        }
        return kosten;
    }

    @Override
    public String toString() {
        String str = super.toString();
        str += isFacharbeiter() ? ", Facharbeiter" : ", Hilfsarbeiter";
        return str;
    }
}

Fehler: super nicht in der ersten Zeile

super(…) muss die erste Anweisung im Konstruktor sein; die Set-Methoden für eigene Attribute folgen danach.

Frage 1 Welche Probleme löst Vererbung?

Mehrere Antworten sind richtig.

Erklärung: Gemeinsame Attribute und Methoden mehrerer Klassen stehen nur einmal in einer Basisklasse statt dupliziert in jeder Klasse. Eine Änderung an der gemeinsamen Logik macht man deshalb nur an einer Stelle. Schneller werden Programme dadurch nicht.

Frage 2 Was muss im Konstruktor einer Unterklasse als erste Anweisung stehen, wenn die Basisklasse keinen parameterlosen Konstruktor hat?

Erklärung: Zuerst wird der Teil der Basisklasse aufgebaut. Fehlt der super-Aufruf, versucht Java einen parameterlosen Basiskonstruktor zu verwenden – gibt es keinen, übersetzt der Code nicht.

Frage 3 Tier t = new Hund(); t.lautGeben(); – Hund erbt von Tier und überschreibt lautGeben(). Welche Methode wird ausgeführt?

Erklärung: Das ist Polymorphismus: Entscheidend ist der Typ des Objekts zur Laufzeit, nicht der Typ der Variable. Die überschriebene Methode der Unterklasse gewinnt.

Frage 4 Was liefert String s = (x < 10) ? "klein" : "groß"; bei x = 12?

Erklärung: Der ternäre Operator bedingung ? a : b liefert a, wenn die Bedingung wahr ist, sonst b. 12 < 10 ist falsch.
