1 — Aufbau einer Methode

Methoden schreibst du schon seit Lektion 1.2. Jetzt sehen wir uns ihren Aufbau genauer an. Eine Methode setzt sich aus Methodenkopf und Methodenrumpf zusammen. Der Kopf enthält Zugriffs-Modifier, Rückgabewert, Namen und eine (möglicherweise leere) Parameterliste.

Zugriffs-Modifier

Der Zugriffs-Modifier steuert die Sichtbarkeit. Alle private gesetzten Elemente sind außerhalb der Klasse nicht sichtbar – sie können von dort nicht aufgerufen werden. public bedeutet: überall sichtbar, auch für Methoden anderer Klassen. Methoden, die nur innerhalb der Klasse verwendet werden sollen, werden private gesetzt, alle anderen public.

Rückgabewert

Der Rückgabewert ist entweder eine zurückgegebene Eigenschaft oder das Ergebnis einer Berechnung. Er ist ein Datentyp (primitiv oder Referenz) oder void – dann wird nichts zurückgegeben. Ist der Rückgabewert nicht void, muss die Methode mindestens ein return-Statement enthalten; der zurückgegebene Typ muss zum Methodenkopf passen. Bei Referenzdatentypen ist grundsätzlich auch null möglich.

Parameter: call-by-value

Bei primitiven Datentypen wird der übergebene Wert in den Parameter kopiert. Änderungen des Parameters innerhalb der Methode haben keine Auswirkungen außerhalb.

Bei Referenzdatentypen wird nur der Verweis auf das Objekt übergeben (oft call-by-reference genannt). Änderungen am Objekt über diesen Verweis wirken daher auch außerhalb der Methode – es gibt keine Kopie des Objekts. Meist ist es ratsam, als Parameter übergebene Objekte nicht zu verändern, wenngleich das manchmal genau das gewünschte Verhalten ist.

Parameterübergabe Java 
public void verdoppeln(int zahl) {
    zahl = zahl * 2;              // nur die Kopie ändert sich
}

public void umbenennen(Student s) {
    s.setName("Neuer Name");      // das Objekt des Aufrufers ändert sich
}
ℹ
Präzisierung

Genau genommen kopiert Java immer den Inhalt der Variablen – bei Referenztypen ist das die Referenz. Weist man dem Parameter ein neues Objekt zu (s = new Student();), bleibt die Variable des Aufrufers unverändert. Verändert wird nur, was man über die Referenz am Objekt ändert.

Methoden rufen Methoden auf

Methoden können in der Object Workbench über das Menü einer Objekt-Karte aufgerufen werden, innerhalb der Klasse aber auch direkt über ihren Namen:

Student.java Java 
public class Student {

    private String name;
    private int geburtsjahr;

    // Konstruktoren und Get-/Set-Methoden wurden hier (teilweise) ausgelassen

    public int getGeburtsjahr() {
        return geburtsjahr;
    }

    public int alterBerechnen(int aktuellesJahr) {
        return aktuellesJahr - getGeburtsjahr();
    }
}

2 — Signatur und Überladen

Die Signatur einer Methode ist gegeben durch den Methodennamen sowie Typen und Reihenfolge der Parameter. In einer Klasse dürfen nicht mehrere Methoden mit derselben Signatur vorkommen. Mehrere Methoden mit gleichem Namen sind sehr wohl zulässig, wenn sie sich in den Parametern unterscheiden – man nennt das Überladen.

SignaturDemo.java (Rümpfe weggelassen) Java 
public class SignaturDemo {

    public int foo(int a, int b) {
        // TODO
    }

    public int foo(int a) { // Zulässig, da andere Parameteranzahl als obige Methode
        // TODO
    }

    public int foo(double a, double b) { // Zulässig, da andere Parametertypen
        // TODO
    }

    public double foo(int a) { // Unzulässig, da schon eine Methode mit Namen foo und
                               // einem int-Parameter existiert. Es ist hierbei
                               // unerheblich, dass sich der Rückgabewert unterscheidet.
                               // Es handelt sich dennoch um die gleiche Signatur wie
                               // in der zweiten Methode.
        // TODO
    }
}

Überladen ist sinnvoll, wenn man sehr ähnliche Aufgaben mit unterschiedlichen Parametern durchführen möchte – etwa die Summe von int- und von double-Werten:

Berechnung.java Java 
public class Berechnung {

    public int summe(int a, int b) {
        return a + b;
    }

    public double summe(double a, double b) {
        return a + b;
    }
}

Auch Konstruktoren lassen sich überladen – das hast du mit Student() und Student(String, int) bereits gemacht.

3 — Einstiegspunkt: die Methode main()

Bisher hast du Methoden in der Object Workbench per Mausklick aufgerufen. Ein Programm startet dagegen von selbst – und zwar immer an derselben Stelle: der Methode main, dem Einstiegspunkt. Am einfachsten schreibst du sie in eine eigene Datei, z. B. Main.java. Diese Datei enthält nur die Methode, keine Klasse drumherum:

Main.java Java 
void main() {
    Student s = new Student("Peter Huber", 2005);
    s.printStudent();
    System.out.println(s.alterBerechnen(2026));
}

Neben main zeigt IntelliJ einen grünen Pfeil. Ein Klick darauf startet das Programm: Java führt die Anweisungen in main der Reihe nach aus und beendet das Programm nach der letzten. Die Ausgaben erscheinen unten im Fenster Run.

ℹ
Die lange Form

Diese kurze Schreibweise gibt es seit Java 25. In älterem Code steht main in einer Klasse und hat einen längeren Kopf (public static void main(String[] args)) – was der bedeutet, lernst du in Lektion 1.11.

Projektschritt

Projektschritt 1.5

Überladener Konstruktor und überladene Kostenmethode

Es gibt jetzt drei überladene Konstruktoren – der neue setzt alle vier Eigenschaften auf einmal – und zwei überladene Methoden getKostenProMonat: eine für beliebig viele Wochen, eine vereinfachte für 4 Wochen, die die erste aufruft (Code-Wiederverwendung). Neu:

src/main/java/Mitarbeiter.java (Auszug) Java 
public Mitarbeiter(String name, int geburtsjahr, int stundenlohn,
                   int anzahlWochenStunden)
{
    setName(name);
    setGeburtsjahr(geburtsjahr);
    setStundenlohn(stundenlohn);
    setAnzahlWochenStunden(anzahlWochenStunden);
}

// überladen: Kosten für eine bestimmte Anzahl an Wochen ...
public int getKostenProMonat(int anzahlWochen) {
    return anzahlWochen * stundenlohn * anzahlWochenStunden;
}

// ... und vereinfacht mit 4 Wochen pro Monat (Code-Wiederverwendung)
public int getKostenProMonat() {
    return getKostenProMonat(4);
}

Probiere in der Object Workbench: new Mitarbeiter("Karl Maier", 1989, 15, 40) → getKostenProMonat() liefert 2400, getKostenProMonat(5) liefert 3000.

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Überladen nur über den Rückgabetyp

int foo(int a) und double foo(int a) → method foo(int) is already defined.

Der Rückgabetyp gehört nicht zur Signatur. Überladene Methoden müssen sich in Anzahl, Typ oder Reihenfolge der Parameter unterscheiden.

Fehler: missing return statement

Eine Methode mit Rückgabetyp int übersetzt nicht, weil ein return fehlt.

Jede Methode, die nicht void ist, muss auf jedem Weg einen Wert des passenden Typs zurückgeben: return …;.

Fehler: Private Methode von außen aufgerufen

m.hilfsmethode() in einer anderen Klasse → hilfsmethode() has private access in Mitarbeiter.

private ist nur innerhalb der eigenen Klasse sichtbar. Soll die Methode von außen nutzbar sein, muss sie public sein.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was gehört zur Signatur einer Methode?

Mehrere Antworten sind richtig.

Erklärung: Die Signatur besteht aus Name sowie Typen und Reihenfolge der Parameter. Rückgabetyp und Parameternamen gehören nicht dazu – int foo(int a) und double foo(int b) haben dieselbe Signatur und dürfen nicht gemeinsam in einer Klasse stehen.

Frage 2 Eine Methode bekommt einen int-Parameter und weist ihm im Rumpf einen neuen Wert zu. Was passiert mit der Variable, die der Aufrufer übergeben hat?

Erklärung: Bei primitiven Typen wird der Wert in den Parameter kopiert (call-by-value). Die Methode ändert nur ihre Kopie.

Frage 3 Welche Methoden dürfen zusammen mit int summe(int a, int b) in einer Klasse stehen?

Mehrere Antworten sind richtig.

Erklärung: Überladene Methoden müssen sich in Anzahl, Typ oder Reihenfolge der Parametertypen unterscheiden. Ein anderer Rückgabetyp oder andere Parameternamen reichen nicht.

Frage 4 Eine Datei Main.java enthält nur void main() { … }, ohne Klasse drumherum. Was passiert beim Start?

Erklärung: main ist der Einstiegspunkt eines Programms. Seit Java 25 genügt diese kurze Form in einer eigenen Datei; daneben gibt es die klassische Form public static void main(String[] args) innerhalb einer Klasse.
