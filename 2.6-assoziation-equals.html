Beidseitige Assoziation & equals

Assoziation ca. 90 min Fortgeschritten

Lernziele

  • einseitige und beidseitige Assoziation unterscheiden und im UML-Diagramm erkennenAbschnitt 1
  • eine beidseitige Assoziation so implementieren, dass beide Seiten immer konsistent sindAbschnitt 3
  • verhindern, dass ein Objekt gleichzeitig zwei „Besitzern“ zugeordnet istAbschnitt 2
  • Referenzgleichheit (==) und Inhaltsgleichheit (equals) unterscheidenAbschnitt 4
  • eine eigene equals-Methode nach dem Standardmuster schreibenAbschnitt 4

1 — Einseitig reicht oft nicht

Beim Beispiel Markt – Stand wurde eine einseitige Assoziation umgesetzt. Der Pfeil im UML-Diagramm von Markt zu Stand zeigt: Von einem Markt gelangt man zu seinen Ständen, aber nicht umgekehrt. Hat man im Programm nur ein Stand-Objekt, kann man nicht feststellen, auf welchem Markt es steht.

Außerdem wäre es möglich, ein und dasselbe Stand-Objekt auf mehreren Märkten zu platzieren – nicht das gewünschte Verhalten.

Beide Probleme löst die beidseitige Assoziation: Der Stand bekommt eine Objekteigenschaft, die auf den Markt verweist, dem er zugeordnet ist. Ist er keinem Markt zugeordnet, ist sie null. Der Code muss sicherstellen, dass dieses Attribut immer konsistent gesetzt ist.

2 — Die Seite des Stands

Stand.java (Erweiterung) Java 
public class Stand {

    // ...

    private Markt markt; // enthaelt Markt auf dem der Stand steht

    public Stand() {
        setName("n/a");
        setEssen(false);
        setUmsatz(0);
        markt = null; // <--- Erweiterung fuer die beidseitige Assoziation
    }

    // in den anderen Konstruktoren ebenso: markt = null;

    public Markt getMarkt() {
        return markt;
    }

    public void setMarkt(Markt markt) {
        if (markt != null) {
            if (markt.hasStand(this)) {
                this.markt = markt;
            } else {
                System.out.println("Fehler: Markt kann nicht gesetzt werden, da Stand "
                                   + getName() + " nicht vorhanden in " + markt.getName());
            }
        } else {
            if (this.markt == null || !this.markt.hasStand(this)) {
                this.markt = null;
            } else {
                System.out.println("Fehler: Kann Markt nicht null setzten, weil Stand "
                                   + getName() + " noch auf Markt " + this.markt.getName()
                                   + " steht.");
            }
        }
    }

    // ...
}

setMarkt setzt den übergebenen Markt nur, wenn dieser Markt den Stand tatsächlich enthält. Zum Entfernen wird null übergeben; dann wird this.markt nur auf null gesetzt, wenn der bisherige Markt den Stand nicht mehr enthält. So kann niemand von außen eine inkonsistente Zuordnung herstellen.

3 — Die Seite des Markts

Markt.java (Ergänzungen) Java 
public class Markt {

    // ...

    public boolean hinzufuegen(Stand stand) {
        boolean hinzugefuegt = false;
        if (stand != null) {
            if (anzahl < staende.length) { // Platz vorhanden?
                if (stand.getMarkt() == null) { // beidseitige Assoziation
                    staende[anzahl++] = stand;
                    stand.setMarkt(this); // beidseitige Assoziation

                    hinzugefuegt = true;
                } else {
                    System.out.println("Stand steht schon auf Markt " + stand.getMarkt().getName());
                }
            } else {
                System.out.println("Stand konnte nicht eingefuegt werden, kein Platz vorhanden.");
            }
        } else {
            System.out.println("Fehler: uebergebener Stand ist null.");
        }
        return hinzugefuegt;
    }

    public Stand entfernen(String name) {
        if (name != null) {
            for (int i = 0; i < anzahl; i++) {
                if (name.equals(staende[i].getName())) {
                    return entfernen(i);
                }
            }
            System.out.println("Es wurde kein Stand mit dem uebergebenen Namen gefunden.");
        } else {
            System.out.println("Fehler: name ist null.");
        }

        return null;
    }

    public Stand entfernen(int pos) {
        Stand s = null;
        if (pos >= 0 && pos < anzahl) {
            s = staende[pos];
            for (int i = pos; i < anzahl - 1; i++) {
                staende[i] = staende[i+1];
            }
            anzahl--;
            staende[anzahl] = null;
            s.setMarkt(null); // beidseitige Assoziation: erst NACH dem Entfernen
        } else {
            System.out.println("Fehler: ungueltige Position " + pos);
        }

        return s;
    }

    // ...
}

Vor dem Hinzufügen wird u. a. geprüft, ob stand.getMarkt() == null gilt, der Stand also nicht schon auf einem anderen Markt steht. Dann wird er ins Array eingefügt (staende[anzahl++] = stand;) und im Stand die Referenz auf diesen Markt gesetzt (stand.setMarkt(this);). Die Reihenfolge ist wichtig: setMarkt akzeptiert den Markt nur, wenn er den Stand schon enthält – beim Entfernen umgekehrt erst, wenn er ihn nicht mehr enthält.

💡
Merksatz

Eine Seite ist „führend“ (hier: der Markt). Nur ihre Methoden (hinzufuegen, entfernen) ändern die Zuordnung und rufen dabei die Set-Methode der anderen Seite auf. Die andere Seite prüft nur, ob der Aufruf zum aktuellen Zustand passt.

4 — Inhaltsgleichheit vs. Referenzgleichheit

Bei primitiven Datentypen wird Gleichheit ausschließlich mit == geprüft. Für Referenzdatentypen ist == auch definiert, hat aber eine speziellere Bedeutung: Es prüft, ob zwei Objektreferenzen auf dasselbe Objekt verweisen.

Manchmal braucht man aber einen Test auf Inhaltsgleichheit. Dafür gibt es die equals-Methode, die du schon von String kennst: Sie liefert true, wenn das Objekt und der Parameter inhaltlich übereinstimmen – auch wenn es verschiedene Instanzen sind. Damit eigene Klassen das können, muss equals implementiert werden:

Student.java Java 
public class Student {
    private String name;
    private int geburtsjahr;

    // Konstruktoren und Getter/Setter hier weggelassen

    @Override
    public boolean equals(Object other) {
        if (other == null) return false;
        if (this == other) return true;
        if (this.getClass() != other.getClass()) return false;

        Student otherStud = (Student) other;

        if (this.name.equals(otherStud.name) && this.geburtsjahr == otherStud.geburtsjahr) {
            return true;
        }
        return false;
    }
}
  1. Ist der Parameter null, wird false zurückgegeben.
  2. Ist der Parameter dieselbe Referenz wie this, liegt auf jeden Fall Inhaltsgleichheit vor.
  3. Stammen beide Objekte nicht aus derselben Klasse, sind sie verschieden. Sonst wird other in einen Student umgewandelt (Cast).
  4. Dann werden die einzelnen Attribute verglichen – Strings wiederum mit equals, primitive Typen mit ==.

@Override zeigt an, dass eine geerbte Methode überschrieben wird (Details in Lektion 2.8). equals wird am besten von der IDE erzeugt (Alt+Einfg → equals() and hashCode()) und eventuell geringfügig angepasst.

Vergleich ==/equals Java 
Student s1 = new Student("Peter", 2001);
Student s2 = s1;
Student s3 = new Student("Peter", 2001);
Student s4 = new Student("Lisa", 2003);

System.out.println("s1 == s2: " + (s1 == s2));
System.out.println("s1 == s3: " + (s1 == s3));
System.out.println("s1.equals(s3): " + (s1.equals(s3)));
System.out.println("s1.equals(s4): " + (s1.equals(s4)));
Ausgabe Text 
s1 == s2: true
s1 == s3: false
s1.equals(s3): true
s1.equals(s4): false
⚠
Regeln für equals

Bei der Implementierung ist darauf zu achten, dass aus x.equals(y) auch y.equals(x) folgt (symmetrisch) und x.equals(x) klarerweise true liefert (reflexiv). Und: Wer equals überschreibt, sollte auch hashCode überschreiben (Lektion 3.2).

Mitarbeiter kennt seine Firma

Jeder Mitarbeiter weiß jetzt, in welcher Firma er arbeitet (getFirma()), und kann nicht gleichzeitig bei zwei Firmen angestellt sein. Die Firma ist die führende Seite: einfuegen und kuendigen(int) halten beide Seiten konsistent. Außerdem bekommt der Mitarbeiter eine equals-Methode (gleicher Name und gleiches Geburtsjahr).

    return firma;
}

public void setFirma(Firma firma) {
    if (firma != null) {

            this.firma = firma;

            System.out.println("Fehler: " + name + " ist nicht in Firma "
                               + firma.getName() + " eingetragen.");
        }

        if (this.firma == null || !this.firma.enthaelt(this)) {
            this.firma = null;
        } else {
            System.out.println("Fehler: " + name + " arbeitet noch in Firma "
                               + this.firma.getName() + ".");
        }

}

// Inhaltsgleichheit: gleicher Name und gleiches Geburtsjahr

public boolean equals(Object other) {
    if (other == null) return false;

    return this.name.equals(m.name) && this.geburtsjahr == m.geburtsjahr;

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Nur eine Seite aktualisiert

Nach markt.entfernen("Langos") liefert stand.getMarkt() immer noch den alten Markt; der Stand kann nirgends mehr hinzugefügt werden.

Jede Änderung der Zuordnung muss beide Seiten anpassen: Array und setMarkt. Am besten nur über die Methoden der führenden Seite ändern.

Fehler: Falsche Reihenfolge

stand.setMarkt(this) wird vor dem Einfügen ins Array aufgerufen – die Fehlermeldung „Stand nicht vorhanden“ erscheint.

Beim Hinzufügen zuerst ins Array, dann setMarkt(this); beim Entfernen zuerst aus dem Array, dann setMarkt(null).

Fehler: equals mit falschem Parametertyp

public boolean equals(Student other) wird von ArrayList.contains & Co. nie aufgerufen.

Die Signatur muss exakt equals(Object other) lauten – sonst ist es eine Überladung, keine Überschreibung. @Override davor lässt den Compiler das prüfen.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was bedeutet eine beidseitige Assoziation zwischen zwei Klassen A und B?

Erklärung: Bei beidseitiger Assoziation hat jede Seite eine Referenz auf die andere. Damit das konsistent bleibt, müssen beide Seiten immer gemeinsam geändert werden.

Frage 2 Bei einer beidseitigen Assoziation ist ein Objekt bereits dem „Besitzer“ X zugeordnet und soll zum Besitzer Y wechseln. Was muss passieren?

Erklärung: Ein Objekt darf nicht gleichzeitig zwei Besitzern gehören, und beide Seiten der Beziehung müssen nach jeder Änderung zueinander passen.

Frage 3 Zwei Objekte derselben Klasse wurden mit denselben Daten getrennt erzeugt. Was liefert o1 == o2?

Erklärung: == prüft Referenzgleichheit. Ob zwei Objekte inhaltlich gleich sind, beantwortet erst eine selbst geschriebene equals-Methode.

Frage 4 Welche Schritte gehören zum Standardmuster einer equals(Object o)-Methode?

Mehrere Antworten sind richtig.

Erklärung: Nach den Prüfungen auf dasselbe Objekt, null und die Klasse werden die fachlich wichtigen Attribute verglichen – Strings und andere Objekte dabei wieder mit equals.
