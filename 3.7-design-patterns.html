1 — Was sind Design-Patterns?

Design-Patterns sind bewährte Entwurfsmuster für häufig auftretende Anforderungen. Im Standardwerk Design Patterns. Elements of Reusable Object-Oriented Software stellen Erich Gamma, Richard Helm, Ralph Johnson und John Vlissides (oft „Gang of Four“, GoF, genannt) 23 Entwurfsmuster vor, eingeteilt in Erzeugungs-, Struktur- und Verhaltensmuster. Ein Pattern ist kein fertiger Code, sondern eine Lösungsidee mit Namen – wer „das ist ein Singleton“ sagt, wird von anderen Entwicklerinnen und Entwicklern sofort verstanden. Einigen Patterns bist du schon begegnet:

Design-Patterns ausführlich vorzustellen, würde den Rahmen sprengen – siehe das Buch der GoF oder Online-Quellen. Die folgenden Abschnitte zeigen die drei wichtigsten genauer.

2 — Singleton

Manchmal darf es von einer Klasse nur ein Objekt geben, z. B. die Konfiguration eines Programms oder die Firma, mit der alle Seiten einer Webanwendung arbeiten. Das Singleton erreicht das mit drei Zutaten: Die Konstruktoren sind private; eine statische Variable hält die einzige Instanz; eine statische Methode gibt sie zurück und erzeugt sie beim ersten Aufruf.

Singleton (Grundgerüst) Java 
public class Konfiguration {

    private static Konfiguration instanz = null;

    private Konfiguration() {        // niemand außer der Klasse selbst kann erzeugen
    }

    public static Konfiguration getInstance() {
        if (instanz == null) {
            instanz = new Konfiguration();
        }
        return instanz;
    }
}
Verwendung Java 
Konfiguration k1 = Konfiguration.getInstance();
Konfiguration k2 = Konfiguration.getInstance();
System.out.println(k1 == k2);        // true – dasselbe Objekt
// new Konfiguration();             // Fehler: Konfiguration() has private access
⚠
Singleton sparsam einsetzen

Ein Singleton ist im Grunde eine globale Variable: Jede Klasse kann darauf zugreifen und es verändern. Besonders bei Tests ist das lästig, weil alle Tests dieselbe Instanz teilen. In Lektion 3.8 verwenden wir es bewusst für die Firma der Webanwendung; in der Personalverwaltung bleibt Firma eine normale Klasse, damit jeder Test seine eigene Firma anlegen kann.

3 — Factory

Eine Factory-Methode ist eine statische Methode, die ein Objekt erzeugt und zurückgibt. Das hat zwei Vorteile gegenüber new: Sie kann einen sprechenden Namen haben (wertVon, ausCsv), und sie kann je nach Eingabe entscheiden, welche Klasse erzeugt wird. Wer sie aufruft, kennt nur den Rückgabetyp – oft eine abstrakte Basisklasse oder ein Interface.

Factory: der Aufrufer kennt nur Person Java 
Person p = Person.ausCsv("Freelancer;Sepp Gruber;1981;3;300");
System.out.println(p.getKostenProMonat());   // 900 – es ist ein Freelancer

Kommt später ein neuer Personentyp dazu (z. B. Praktikant), muss nur die Factory-Methode ergänzt werden – alle Stellen, die Personen aus CSV-Zeilen erzeugen, bleiben unverändert. Wie die Methode aussieht, zeigt der Projektschritt.

4 — Strategy

Beim Strategy-Pattern wird ein Teil eines Algorithmus austauschbar gemacht: Der Algorithmus bekommt die „Strategie“ als Objekt übergeben, meist als Interface. Genau das passiert beim Sortieren mit einem Comparator (Lektion 3.5): sort kennt den Sortieralgorithmus, der Comparator bestimmt, was „kleiner“ heißt. Seit es Lambdas gibt, ist eine Strategie oft nur noch eine Zeile:

Strategy mit Comparator Java 
public List<Person> sortiert(Comparator<Person> strategie) {
    ArrayList<Person> sortiert = new ArrayList<>(personal);
    sortiert.sort(strategie);
    return sortiert;
}

// Aufruf mit verschiedenen Strategien
firma.sortiert(Comparator.comparing(Person::getName));
firma.sortiert((a, b) -> b.getKostenProMonat() - a.getKostenProMonat());

Projektschritt

Projektschritt 3.7

Eine Factory-Methode für Personen

readFromFile entscheidet bisher selbst mit einer if-Kette, welche Unterklasse aus einer CSV-Zeile entsteht. Diese Entscheidung wandert jetzt in die Factory-Methode Person.ausCsv. Sie ist im Fail-Early-Stil geschrieben: jeder Typ ein eigenes return, am Ende die Exception.

src/main/java/Person.java (Auszug) Java 
// Factory-Methode: erzeugt anhand der ersten CSV-Spalte das passende Objekt.
// Wer sie aufruft, muss die Unterklassen nicht kennen.
public static Person ausCsv(String zeile) throws FirmaException {
    if (zeile == null || zeile.isBlank()) {
        throw new FirmaException("Leere CSV-Zeile");
    }
    if (zeile.startsWith("Arbeiter;")) {
        return new Arbeiter(zeile);
    }
    if (zeile.startsWith("Angestellter;")) {
        return new Angestellter(zeile);
    }
    if (zeile.startsWith("Freelancer;")) {
        return new Freelancer(zeile);
    }
    throw new FirmaException("Ungueltiger Personentyp in Zeile " + zeile);
}
src/main/java/Firma.java (Auszug aus readFromFile) Java 
while (line != null) {
    if (!line.isBlank()) {
        firma.einstellen(Person.ausCsv(line));   // Factory-Methode
    }
    line = br.readLine();
}

Die abstrakte Klasse Person kann zwar selbst nicht instanziiert werden, eine statische Methode darf sie aber trotzdem haben. FactoryTest prüft, dass für jeden Typ die richtige Unterklasse entsteht (assertInstanceOf) und unbekannte Typen eine FirmaException auslösen.

Fehler: Singleton mit öffentlichem Konstruktor

Trotz getInstance() gibt es plötzlich zwei Konfigurationen.

Irgendwo wurde new Konfiguration() aufgerufen. Beim Singleton müssen alle Konstruktoren private sein.

Fehler: Factory-Methode nicht statisch

Person.ausCsv(line) → non-static method ausCsv(String) cannot be referenced from a static context.

Eine Factory-Methode wird aufgerufen, bevor es ein Objekt gibt – sie muss static sein.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Was sind Design-Patterns?

Erklärung: Ein Pattern ist eine Idee, kein fertiger Code. Die gemeinsamen Namen (Singleton, Factory, …) erleichtern auch die Verständigung im Team.

Frage 2 Was gehört zu einer typischen Singleton-Implementierung?

Mehrere Antworten sind richtig.

Erklärung: Weil niemand von außen new aufrufen kann, gibt es nur das eine Objekt, das getInstance() zurückgibt.

Frage 3 Was macht eine Factory-Methode?

Erklärung: Der Aufrufer muss nicht wissen, welche konkrete Unterklasse entsteht – das entscheidet die Factory. „Nur ein Objekt“ beschreibt dagegen das Singleton.

Frage 4 Warum ist ein Comparator, der an sort übergeben wird, ein Beispiel für das Strategy-Pattern?

Erklärung: Strategy trennt einen Algorithmus von einem austauschbaren Teil. Mit einem anderen Comparator sortiert dieselbe Methode nach einem anderen Kriterium.
