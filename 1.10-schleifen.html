1 — Die while-Schleife

Schleifen sind zentrale Sprachkonstrukte in allen Programmiersprachen: Sie führen bestimmte Codestücke mehrmals aus. Es gibt verschiedene Ausprägungen – zwei while-Schleifen und die for-Schleife. Allen gemeinsam ist eine Zählvariable, die (meist) angibt, wie oft die Schleife schon durchlaufen wurde, und die in jedem Durchlauf verändert (hochgezählt, „inkrementiert“) wird. Eine Fortsetzungsbedingung legt fest, ob die Schleife erneut ausgeführt wird.

Die folgende Methode schreibt eine Linie aus --Zeichen, deren Länge per Parameter gesteuert wird:

zeichneLinie Java 
public void zeichneLinie(int laenge) {
    if (laenge >= 0) {
        int zaehler = 0;
        while (zaehler < laenge) {
            System.out.print("-");
            zaehler++; // entspricht: zaehler = zaehler + 1;
        }

        System.out.println();
    } else {
        System.out.println("Fehler: laenge ungueltig: " + laenge);
    }
}
  • int zaehler = 0; – Initialisierung der Schleifenvariable.
  • while (zaehler < laenge) – die Bedingung (ein Ausdruck mit Ergebnis boolean) wird vor jedem Durchlauf geprüft.
  • Im Block wird ein Zeichen ausgegeben (print ohne Zeilenumbruch) und danach die Zählvariable erhöht.
  • System.out.println() nach der Schleife beendet die Zeile.
✗
Endlosschleife

Wird vergessen, die Schleifenvariable zu verändern, entsteht eine Endlosschleife: Das Programm läuft, ohne etwas Sinnvolles zu tun, bis es manuell unterbrochen wird – z. B. mit Strg+C oder dem Stopp-Button der IDE. Die Object Workbench bricht hängende Methodenaufrufe nach einem Zeitlimit ab.

2 — do-while und for

Von der while-Schleife gibt es eine Variante, bei der die Bedingung am Ende steht – der Rumpf wird also mindestens einmal ausgeführt:

do-while Java 
public void zahlenAusgeben() {
    int i = 0;
    do {
        System.out.println(i);
        i++;
    } while (i < 10);
}

Manchmal ist diese Schleife „eleganter“, nötig ist sie nicht: Jede while-Schleife kann in eine do-while-Schleife umgeschrieben werden und umgekehrt.

Auch die for-Schleife ist nur eine andere Schreibweise und kann durch while ersetzt werden. Das vorige Beispiel sieht so aus:

for Java 
public void zahlenAusgeben2() {
    for (int i = 0; i < 10; i++) {
        System.out.println(i);
    }
}
Teil des SchleifenkopfsBedeutung
int i = 0Schleifenvariable und Initialisierung. Syntaktisch wäre auch double zulässig – das ist aber nahezu immer ein Fehler.
i < 10Bedingung, unter der die Schleife erneut durchlaufen wird; auch komplexere boolesche Ausdrücke sind möglich, aber selten nötig
i++Veränderung der Schleifenvariable; möglich ist z. B. auch i += 2 oder i -= 4, meist aber i++ oder i--
💡
Welche Schleife wann?
for, wenn die Anzahl der Durchläufe vorher feststeht (zählen); while, wenn solange wiederholt wird, bis eine Bedingung eintritt; do-while, wenn mindestens ein Durchlauf nötig ist.

3 — Beispiel: Quadrat mit Diagonale

Eine Klasse Quadrat soll ein Quadrat mit einer Diagonale von links oben nach rechts unten ausgeben:

Ausgabe (laenge = 11) Text 
###########
##        #
# #       #
#  #      #
#   #     #
#    #    #
#     #   #
#      #  #
#       # #
#        ##
###########

Je nach Schriftart sieht das mehr oder weniger quadratisch aus – die Anzahl der Zeichen pro Zeile entspricht aber der Anzahl der Zeilen. printQuadrat verwendet zwei Schleifen, die durch Zeilen und Spalten laufen. Die If-Bedingung entscheidet, ob # oder ein Leerzeichen zu zeichnen ist (das Leerzeichen ist nötig, sonst rückt der rechte Rand nach links):

  • erste oder letzte Zeile: zeile == 0 || zeile == laenge-1
  • erste oder letzte Spalte: spalte == 0 || spalte == laenge-1
  • Diagonale: Zeilenindex gleich Spaltenindex, zeile == spalte
Quadrat.java Java 
public class Quadrat {

    private int laenge;

    public Quadrat() {
        setLaenge(10);
    }

    public Quadrat(int laenge) {
        setLaenge(laenge);
    }

    public int getLaenge() {
        return laenge;
    }

    public void setLaenge(int laenge) {
        if (laenge > 0 && laenge < 100) {
            this.laenge = laenge;
        } else {
            System.out.println("Fehler: ungueltige Laenge: " + laenge);
        }
    }

    public void printQuadrat() {
        int zeile = 0;
        while (zeile < laenge) {
            int spalte = 0;
            while (spalte < laenge) {
                if (zeile == 0 || zeile == laenge-1
                    || spalte == 0 || spalte == laenge-1
                    || zeile == spalte)
                {
                    System.out.print("#");
                } else {
                    System.out.print(" ");
                }
                spalte++;
            }
            System.out.println();
            zeile++;
        }
    }
}

Übungsaufgabe (versuche es zuerst selbst): Eine Methode printQuadrat2 soll statt dieser Diagonale die andere zeichnen – von rechts oben nach links unten, mit dem Zeichen *:

Quadrat.java – Lösung printQuadrat2 Java 
public void printQuadrat2() {
    int zeile = 0;
    while (zeile < laenge) {
        int spalte = 0;
        while (spalte < laenge) {
            if (zeile == 0 || zeile == laenge-1
                || spalte == 0 || spalte == laenge-1)
            {
                System.out.print("#");
            } else if (spalte == laenge-1-zeile) {
                System.out.print("*");
            } else {
                System.out.print(" ");
            }
            spalte++;
        }
        System.out.println();
        zeile++;
    }
}

4 — Beispiel: Rechtecke mit Code-Wiederverwendung

Rechtecke und Quadrate sollen in beliebiger Größe, mit Einrückung und frei wählbaren Zeichen gezeichnet werden („parametrierbar“):

Rechteck mit # und . Text 
###########
#.........#
#.........#
###########
Rechteck mit @ und _ Text 
@@@@@@@@@@@@@@@@@@
@________________@
@________________@
@________________@
@@@@@@@@@@@@@@@@@@

An diesem Beispiel lässt sich das Prinzip der Code-Wiederverwendung zeigen: Bestimmte Teilaufgaben sollen nicht mehrfach implementiert werden. Das wäre nicht nur Mehrarbeit, spätere Änderungen müssten auch an mehreren Stellen konsistent durchgeführt werden. Mehrfach auftretende, ähnliche Codefragmente sind nahezu immer ein Indiz für schlechtes Design. Schon implementierte Methoden sollen überall dort verwendet werden, wo sie als Teilaufgabe einer größeren Aufgabe auftreten.

Das Zeichnen eines Rechtecks enthält als Teilaufgabe das Zeichnen einer Zeile: Die erste und letzte Zeile bestehen aus lauter gleichen Zeichen, die anderen haben links und rechts ein Randzeichen. Ein eingerücktes Rechteck besteht aus eingerückten Zeilen:

SchleifenDemo.java Java 
public class SchleifenDemo {

    public SchleifenDemo() {
    }

    public void zeichneLinie(int offset, int laenge) {
        zeichneLinie(offset, laenge, '*', '#');
    }

    public void zeichneLinie(int offset, int laenge, char zeichen, char rand) {
        if (offset >= 0) {
            int zaehler = 0;
            while (zaehler < offset) {
                System.out.print(" ");
                zaehler++;
            }
        } else {
            System.out.println("Ungueltiger Offset: " + offset);
        }
        if (laenge >= 0) {
            int zaehler = 0;
            while (zaehler < laenge) {
                if (zaehler == 0 || zaehler == laenge-1) {
                    System.out.print(rand + " ");
                } else {
                    System.out.print(zeichen + " ");
                }
                zaehler++; // zaehler = zaehler + 1;
            }
            System.out.println(); // Zeilenumbruch
        } else {
            System.out.println("Fehler: laenge ungueltig: " + laenge);
        }
    }

    // offset = horizontale Einrueckung
    public void zeichneRechteck(int offset, int laenge, int hoehe, char zeichen, char rand) {
        if (laenge >= 0 && hoehe >= 0) {
            int zeile = 0;
            while (zeile < hoehe) {
                if (zeile == 0 || zeile == hoehe-1) {
                    zeichneLinie(offset, laenge, rand, rand);
                } else {
                    zeichneLinie(offset, laenge, zeichen, rand);
                }
                zeile++;
            }
        } else {
            System.out.println("Fehler, ungueltige laenge oder hoehe: " + laenge + ", " + hoehe);
        }
    }
}
💡
Warum ein Leerzeichen nach jedem Zeichen?
zeichneLinie gibt nach jedem Zeichen ein Leerzeichen aus (rand + " "). Zeichen in der Konsole sind etwa doppelt so hoch wie breit; mit dem Leerzeichen dazwischen sieht das Rechteck deutlich rechteckiger aus – ein Quadrat wirkt dann tatsächlich quadratisch. Die Ausgabe sieht also so aus: # # # # # bzw. # . . . #.

Die Linien-Methoden können unabhängig von der eigentlichen Aufgabe getestet werden. Beim Testen des Rechtecks kann man dann annehmen, dass das Zeichnen einer Linie funktioniert. Und zeichneRechteck ist gut lesbar: Auf der innersten Ebene steht keine komplizierte Schleife, sondern ein selbsterklärender Aufruf von zeichneLinie.

Das Beispiel zeigt auch sinnvolles Überladen: zeichneLinie(int offset, int laenge, char zeichen, char rand) ist frei konfigurierbar, zeichneLinie(int offset, int laenge) ruft sie nur mit Standardwerten auf. Die Weiterführung dieser Idee ergibt Quadrate – ein Quadrat ist nur ein Spezialfall eines Rechtecks mit laenge == hoehe:

SchleifenDemo.java (Ergänzung) Java 
public void zeichneQuadrat(int offset, int laenge) {
   zeichneQuadrat(offset, laenge, '.', '#');
}

public void zeichneQuadrat(int offset, int laenge, char zeichen, char rand) {
    zeichneRechteck(offset, laenge, laenge, zeichen, rand);
}
ℹ
Länge statt Breite

Von der üblichen Bezeichnung Länge/Breite wurde abgewichen, um die Entsprechung zu laenge der Linie hervorzuheben.

Linien und Kosten-Balkendiagramm

Die Firma bekommt Hilfsmethoden mit Schleifen – linie (for) und auffuellen (while) – und gibt die Kosten als Balkendiagramm aus. Der Mitarbeiter liefert dazu seinen Balken (ein # pro angefangenen 500 Euro).

src/main/java/Mitarbeiter.java (neue Methode) Java 
// ein '#' pro angefangenen 500 Euro Kosten, z. B. 2400 Euro -> "#####"
public String kostenBalken() {
    String balken = "";
    int kosten = getKostenProMonat();
    int i = 0;
    while (i < kosten) {
        balken += "#";
        i += 500;
    }
    return balken;
}
src/main/java/Firma.java (neue Methoden) Java 
// Hilfsmethode: liefert eine Linie aus "laenge" gleichen Zeichen
private String linie(char zeichen, int laenge) {
    String s = "";
    for (int i = 0; i < laenge; i++) {
        s += zeichen;
    }
    return s;
}

// Name auf eine fixe Breite mit Leerzeichen auffuellen (fuer Tabellen)
private String auffuellen(String text, int breite) {
    String s = text;
    while (s.length() < breite) {
        s += " ";
    }
    return s;
}

public void printKostenBalken() {
    System.out.println("Kosten pro Monat (# = 500 Euro)");
    System.out.println(linie('=', 47));
    if (ma1 != null) {
        System.out.println(auffuellen(ma1.getName(), 16) + ma1.kostenBalken());
    }
    if (ma2 != null) {
        System.out.println(auffuellen(ma2.getName(), 16) + ma2.kostenBalken());
    }
    if (ma3 != null) {
        System.out.println(auffuellen(ma3.getName(), 16) + ma3.kostenBalken());
    }
    System.out.println(linie('=', 47));
}

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Off-by-one

Die Linie ist ein Zeichen zu lang oder zu kurz, das Quadrat hat eine Zeile zu viel.

Bei Start 0 und < laenge gibt es genau laenge Durchläufe. <= ergibt einen Durchlauf mehr. Im Zweifel mit kleinen Werten (0, 1, 2) durchspielen.

Fehler: Zählvariable der inneren Schleife nicht zurückgesetzt

Beim Quadrat wird nur die erste Zeile gezeichnet, danach nur noch Zeilenumbrüche.

int spalte = 0; muss innerhalb der äußeren Schleife stehen, damit jede Zeile wieder bei Spalte 0 beginnt.

Fehler: Strichpunkt nach dem Schleifenkopf

for (int i = 0; i < 10; i++); – der Rumpf wird nur einmal ausgeführt (bzw. while (…); hängt endlos).

Kein ; direkt nach for (…) oder while (…) – der Strichpunkt ist sonst selbst der (leere) Schleifenrumpf.

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Wie oft wird der Rumpf von for (int i = 0; i < 5; i++) ausgeführt?

Erklärung: i nimmt die Werte 0, 1, 2, 3 und 4 an. Bei i == 5 ist die Bedingung i < 5 falsch, die Schleife endet.

Frage 2 Was unterscheidet do-while von while?

Erklärung: Die Bedingung steht bei do-while hinter dem Rumpf. Ist sie von Anfang an falsch, läuft while gar nicht, do-while einmal.

Frage 3 Warum ist int i = 0; while (i < 10) { System.out.println(i); } eine Endlosschleife?

Erklärung: Jede Schleife braucht eine Anweisung, die sie dem Ende näherbringt – hier fehlt i++.

Frage 4 Mit zwei verschachtelten for-Schleifen soll ein Rechteck aus 3 Zeilen und 4 Spalten # gezeichnet werden. Wie oft wird System.out.print("#") insgesamt ausgeführt?

Erklärung: Die äußere Schleife läuft über die Zeilen (3), die innere für jede Zeile über die Spalten (4): 3 × 4 = 12 Ausgaben.
