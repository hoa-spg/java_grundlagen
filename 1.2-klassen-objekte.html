1 — Klassen modellieren die reale Welt

Klassen sind ein grundlegendes Konzept moderner Programmiersprachen. Sie enthalten den wesentlichen Programmcode; ganze Programme entstehen durch das Zusammenspiel mehrerer Klassen. Eines der wichtigsten Einsatzgebiete: Klassen modellieren Entitäten aus der realen Welt. Eine Anwendung zur Verwaltung von Studenten einer Schule beginnt mit einer Klasse, die einen Studenten modelliert:

Student.java Java 
public class Student {
    private String name;
    private int geburtsjahr;
}

Dieser Student hat zwei Eigenschaften (auch Attribute genannt): einen Namen und ein Geburtsjahr. Der Name ist eine Text-Zeichenkette (String), das Geburtsjahr eine ganze Zahl (int). Die Angaben public und private legen fest, welche Elemente in welchen Programmteilen sichtbar sind – dazu später mehr. Fürs Erste gilt: Eigenschaften sind stets private.

RegelBeispiel
Groß- und Kleinschreibung spielt eine RolleStudent ≠ student
Klassennamen beginnen mit einem GroßbuchstabenStudent, String
Eigenschaften beginnen mit einem Kleinbuchstabenname, geburtsjahr, aber int ist ganz klein
Der Strichpunkt beendet eine Anweisung – ohne ihn lässt sich nichts übersetzenprivate int geburtsjahr;
Alles zwischen { und } wird eingerücktdie Einrückung spiegelt die Struktur des Programms

2 — Klasse und Objekt

Eine Klasse legt fest, welche Daten eine Entität enthält – in unserem Beispiel einen Namen und ein Geburtsjahr. Die Klasse selbst ist nur eine Vorlage (ein „Bauplan“). Konkrete Daten sind z. B. Peter (1981), Sandra (1985), Ercan (1991), Sarah (1994). Solche konkreten Ausprägungen heißen Objekte oder Instanzen.

Klasse Student

  • wird einmal programmiert
  • beschreibt welche Eigenschaften es gibt
  • in IntelliJ: eine Datei Student.java in src/main/java

Objekte (Instanzen)

  • beliebig viele, mit new Student() erzeugt
  • haben eigene Werte: Peter, 1981 – Sandra, 1985
  • in der Object Workbench: eine Karte pro Objekt

Klassen können nicht nur Daten enthalten, sondern auch Methoden: Programmstücke, die mit den Daten rechnen oder sie verändern. Klassen organisieren also das Zusammenspiel von Daten und Programmlogik; Programme entstehen durch die Interaktion mehrerer Objekte.

3 — Get-Methoden

Klassen versuchen zu vermeiden, dass ihre Daten „unkontrolliert“ geändert werden. Durch private kann niemand von außen direkt zugreifen – z. B. ein negatives Geburtsjahr oder einen leeren Namen setzen. Damit man die Werte trotzdem lesen kann, gibt es Get-Methoden:

Student.java Java 
public class Student {
    private String name;
    private int geburtsjahr;

    public String getName() {
        return name;
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }
}
  • beginnt mit public, gefolgt vom Datentyp der Eigenschaft (String bzw. int)
  • danach der Methodenname: get + Name der Eigenschaft mit großem Anfangsbuchstaben
  • nach dem Namen immer runde Klammern, dann geschwungene Klammern mit der Implementierung
  • die einzige Zeile ist das return-Statement: es reicht den Wert an den Aufrufer weiter

4 — Set-Methoden

Set-Methoden ermöglichen es, Eigenschaften zu ändern. Der neue Wert wird als Parameter übergeben:

Student.java Java 
public class Student {
    private String name;
    private int geburtsjahr;

    public String getName() {
        return name;
    }

    public void setName(String neuerName) {
        name = neuerName;
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }

    public void setGeburtsjahr(int neuesGeburtsjahr) {
        geburtsjahr = neuesGeburtsjahr;
    }
}

Der Parameter steht in den runden Klammern der Methodendefinition, mit seinem Datentyp: Da name ein String ist, muss auch der Parameter ein String sein. Im Rumpf wird der Parameter der Eigenschaft zugewiesen: name = neuerName;. Das Schlüsselwort void vor dem Methodennamen sagt: Diese Methode liefert nichts zurück, sie verändert nur das Objekt.

💡
Warum der Umweg?

Gerade weil alle Änderungen durch die Set-Methode laufen, kann man dort später prüfen, ob der neue Wert gültig ist (Lektion 1.6). Ein öffentliches Attribut könnte jeder beliebig überschreiben.

5 — Kommentare

Kommentare stehen im Quelltext, werden vom Compiler aber ignoriert. Es gibt zwei Arten:

Student.java Java 
/*
Dies ist ein mehrzeiliges Kommentar. Am Beginn einer Klasse kann es zum Beispiel
Informationen zum Zweck der Klasse, Autor, Erstellungsdatum etc. enthalten.
*/
public class Student {
    // dies ist ein Kommentar! Diese Zeile wird vom Compiler ignoriert

    private String name;
    private int geburtsjahr;

    public String getName() {
        // Kommentare können auch in Methoden vorkommen!
        return name;
    }

    /*
    public int getGeburtsjahr() {
        return geburtsjahr;
    }
    */
}

Die Methode getGeburtsjahr wurde zur Gänze auskommentiert. Das ist eine gängige Methode, um unfertige oder fehlerhafte Codestücke vor dem Compiler „zu verstecken“.

ℹ
Javadoc

Kommentare, die mit /** beginnen, sind Javadoc-Kommentare. Aus ihnen erzeugt das Werkzeug javadoc eine HTML-Dokumentation – so ist auch die Java-API-Doku entstanden (Lektion 1.8).

Projektschritt

Projektschritt 1.2

Mitarbeiter mit Name und Geburtsjahr

Der Mitarbeiter bekommt seine ersten zwei Eigenschaften, je eine Get- und Set-Methode und einen Kommentar am Anfang. Übersetze, erzeuge ein Objekt und probiere setName und getName in der Object Workbench aus – die Karte des Objekts zeigt nach jedem Aufruf die aktuellen Werte.

src/main/java/Mitarbeiter.java Java 
/*
  Personalverwaltung – die Klasse Mitarbeiter modelliert eine Person,
  die in einer Firma arbeitet.
  Stand: Lektion 1.2 (Attribute, Get- und Set-Methoden)
*/
public class Mitarbeiter {

    // Objekteigenschaften (Attribute)
    private String name;
    private int geburtsjahr;

    // Get-/Set-Methoden
    public String getName() {
        return name;
    }

    public void setName(String neuerName) {
        name = neuerName;
    }

    public int getGeburtsjahr() {
        return geburtsjahr;
    }

    public void setGeburtsjahr(int neuesGeburtsjahr) {
        geburtsjahr = neuesGeburtsjahr;
    }
}

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Get-Methode ohne return

Der Compiler meldet missing return statement.

Jede Methode mit einem Rückgabetyp (nicht void) muss mit return wert; einen Wert dieses Typs zurückgeben.

Fehler: Typ des Parameters passt nicht

public void setGeburtsjahr(String jahr) { geburtsjahr = jahr; } → incompatible types: String cannot be converted to int.

Der Parameter einer Set-Methode hat denselben Datentyp wie die Eigenschaft: int neuesGeburtsjahr.

Fehler: Falsche Groß-/Kleinschreibung

string name; oder Int jahr; führen zu cannot find symbol.

Java unterscheidet Groß- und Kleinschreibung: String (Klasse, groß), int (primitiver Typ, klein). Auch getname() ist eine andere Methode als getName().

Quiz

4 Fragen · zum Aufklappen klicken

Frage 1 Wie verhalten sich Klasse und Objekt zueinander?

Erklärung: Die Klasse beschreibt, welche Eigenschaften und Methoden alle Objekte haben. Von einer Klasse kann man beliebig viele Objekte erzeugen, jedes mit eigenen Attributwerten.

Frage 2 Warum werden Attribute private deklariert?

Erklärung: Über Get- und Set-Methoden behält die Klasse die Kontrolle über ihre Daten – später kann eine Set-Methode z. B. ungültige Werte abweisen. Java würde öffentliche Attribute erlauben, gute Praxis ist es aber nicht.

Frage 3 Welcher Methodenkopf entspricht der Konvention für das Attribut private String name?

Erklärung: Eine Get-Methode hat keinen Parameter und liefert den Wert mit dem Typ des Attributs zurück. Der Name beginnt mit get, gefolgt vom Attributnamen mit großem Anfangsbuchstaben (camelCase). Die Schreibweise getName(): String stammt aus UML, nicht aus Java.

Frage 4 Welche Zeilen sind gültige Kommentare in Java?

Mehrere Antworten sind richtig.

Erklärung: Java kennt einzeilige Kommentare mit // und mehrzeilige mit /* … */. # ist ein Kommentar in Python, <!-- --> in HTML.
