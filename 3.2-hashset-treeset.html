1 — Sets: keine Duplikate

HashSet und TreeSet implementieren das Set-Interface auf jeweils unterschiedliche Art. In einem Set soll sichergestellt sein, dass (inhalts-)gleiche Objekte nicht mehrfach enthalten sind. Damit das funktioniert, muss die equals-Methode implementiert sein.

Ergänzend zu Lektion 2.6: equals ist in Object definiert (alle Klassen leiten von Object ab). Die dortige Implementierung prüft aber nur auf Referenzgleichheit – ob es sich um ein und dasselbe Objekt handelt. Um das zu ändern, muss die Methode überschrieben werden.

Set verwenden Java 
HashSet<String> namen = new HashSet<>();
namen.add("Karl");
namen.add("Susi");
namen.add("Karl");                 // wird ignoriert, add liefert false
System.out.println(namen.size());  // 2
System.out.println(namen.contains("Susi"));   // true

2 — HashSet: equals und hashCode

Zur Verwendung in einem HashSet müssen Klassen zusätzlich die Methode hashCode überschreiben, die ebenfalls in Object definiert ist. Wichtig ist, dass equals und hashCode immer konsistent implementiert werden. Hier der von IntelliJ generierte Code zur Klasse Person (Alt+Einfg → equals() and hashCode()):

Person.java (Auszug) Java 
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Person person = (Person) o;
    return geburtsjahr == person.geburtsjahr && name.equals(person.name);
}

@Override
public int hashCode() {
    return Objects.hash(name, geburtsjahr);
}

getClass() liefert die konkrete Klasse eines Objekts. Für Inhaltsgleichheit wird hier vorausgesetzt, dass auch die Klassen gleich sind. Objects.hash(…) (aus java.util.Objects) berechnet aus denselben Attributen, die equals vergleicht, eine Zahl.

ℹ
Wie ein HashSet funktioniert (kurz)

Ein HashSet verteilt seine Elemente anhand von hashCode() auf „Fächer“ (Buckets). Beim Suchen wird nur im passenden Fach mit equals verglichen – deshalb ist contains sehr schnell. Daraus folgt die Regel: Wenn a.equals(b), dann muss a.hashCode() == b.hashCode() sein. Sonst landen gleiche Objekte in verschiedenen Fächern und das Set erkennt die Duplikate nicht. (Die genauere Darstellung folgt im Theorieunterricht.)

3 — TreeSet

Das TreeSet verhält sich nach außen wie das HashSet – Unterschiede ergeben sich in der Laufzeit der Operationen und in einem wichtigen Detail: Ein TreeSet hält seine Elemente sortiert und verwendet dafür compareTo (Interface Comparable, Lektion 2.9) statt hashCode.

HashSetTreeSet
Reihenfolgenicht festgelegtaufsteigend sortiert
Gleichheit überhashCode + equalscompareTo (0 = gleich)
Voraussetzungequals/hashCode überschriebenComparable implementiert (oder ein Comparator)
Laufzeit von add/containspraktisch konstantwächst langsam (logarithmisch) mit der Größe
⚠
compareTo und equals müssen zusammenpassen

Liefert compareTo für zwei Objekte 0, behandelt das TreeSet sie als gleich – auch wenn equals etwas anderes sagt. compareTo und equals sollten daher zueinander passen.

TreeSet Java 
TreeSet<Person> sortiert = new TreeSet<>(firmenPersonal);   // Kopie, sortiert
System.out.println(sortiert.first().getName());             // alphabetisch erste Person

Projektschritt 3.2

Keine doppelten Personen

Person überschreibt jetzt equals und hashCode (generiert, mit Objects.hash). Die Firma weist inhaltsgleiche Personen (gleicher Name, gleiches Geburtsjahr) mit einer FirmaException zurück und bietet zwei Sets an: eine sortierte Kopie des Personals (TreeSet) und die Menge aller Nachnamen (HashSet).

src/main/java/Firma.java (Auszug) Java 
    if (personal.contains(p)) {          // verwendet equals!
        throw new FirmaException("Fehler: " + p.getName() + " (" + p.getGeburtsjahr()
                                 + ") ist bereits in der Firma.");
    }

// TreeSet: sortiert (compareTo), ohne Duplikate – eine Kopie für die Ausgabe
public TreeSet<Person> personalSortiert() {
    return new TreeSet<>(personal);
}

// HashSet: jeder Nachname nur einmal (Reihenfolge nicht festgelegt)
public HashSet<String> nachnamen() {
    HashSet<String> namen = new HashSet<>();
    for (Person p : personal) {
        String n = p.getName();
        namen.add(n.substring(n.lastIndexOf(" ") + 1));
    }
    return namen;
}
src/test/java/SetTest.java Java 
import static org.junit.jupiter.api.Assertions.*;

import java.util.HashSet;
import java.util.TreeSet;

import org.junit.jupiter.api.Test;

class SetTest {

    @Test
    void hashSetErkenntInhaltsgleichePersonen() throws FirmaException {
        HashSet<Person> set = new HashSet<>();
        set.add(new Freelancer("Sepp Gruber", 1981, 3, 300));
        set.add(new Freelancer("Sepp Gruber", 1981, 5, 900));   // equals -> Duplikat
        set.add(new Freelancer("Sepp Gruber", 1982, 3, 300));
        assertEquals(2, set.size());
    }

    @Test
    void equalsUndHashCodeKonsistent() throws FirmaException {
        Person a = new Angestellter("Anna Novak", 2001, 14, 20, true);
        Person b = new Angestellter("Anna Novak", 2001, 30, 40, false);
        assertEquals(a, b);
        assertEquals(a.hashCode(), b.hashCode());
    }

    @Test
    void treeSetIstSortiert() throws FirmaException {
        TreeSet<Person> set = new TreeSet<>();
        set.add(new Freelancer("Sepp Gruber", 1981, 3, 300));
        set.add(new Arbeiter("Karl Maier", 1989, 15, 40, false));
        set.add(new Angestellter("Anna Novak", 2001, 14, 20, true));
        assertEquals("Anna Novak", set.first().getName());
        assertEquals("Sepp Gruber", set.last().getName());
    }

    @Test
    void firmaVerhindertDuplikate() throws FirmaException {
        Firma firma = new Firma("Spengergasse OG");
        firma.einstellen(new Arbeiter("Karl Maier", 1989, 15, 40, false));
        assertThrows(FirmaException.class,
                     () -> firma.einstellen(new Arbeiter("Karl Maier", 1989, 20, 38, true)));
        assertEquals(1, firma.anzahlMitarbeiter());
    }

    @Test
    void nachnamen() throws FirmaException {
        Firma firma = new Firma("Spengergasse OG");
        firma.einstellen(new Arbeiter("Karl Maier", 1989, 15, 40, false));
        firma.einstellen(new Angestellter("Eva Maier", 1995, 18, 38, true));
        firma.einstellen(new Freelancer("Sepp Gruber", 1981, 3, 300));
        assertEquals(2, firma.nachnamen().size());
        assertTrue(firma.nachnamen().contains("Gruber"));
    }
}

📁 Stand nach dieser Lektion: beispiele/3.2/

Häufige Fehler

Fehler: Nur equals überschrieben

Ein HashSet enthält zwei inhaltsgleiche Personen, obwohl equals true liefert.

Immer auch hashCode überschreiben, mit denselben Attributen wie equals (Objects.hash(name, geburtsjahr)).

Fehler: Objekt nach dem Einfügen verändert

Nach p.setName("Neu") findet set.contains(p) die Person nicht mehr.

Der Hashwert hat sich geändert, das Objekt liegt im „falschen Fach“. Attribute, die in hashCode eingehen, nicht ändern, solange das Objekt in einem HashSet liegt (vorher entfernen, danach wieder einfügen).

Fehler: TreeSet ohne Comparable

ClassCastException: Stand cannot be cast to class java.lang.Comparable beim ersten add.

Elemente eines TreeSet müssen Comparable implementieren – oder man übergibt dem TreeSet einen Comparator (Lektion 3.5).

Wissenskontrolle

Frage 1 Was ist die wichtigste Eigenschaft einer Menge (Set)?

Erklärung: add liefert false, wenn ein gleiches Element schon enthalten ist. Einen Index wie bei der ArrayList gibt es nicht.

Frage 2 Eine Klasse überschreibt equals, aber nicht hashCode. Was kann im HashSet passieren?

Erklärung: HashSet sucht zuerst über den Hashcode den passenden „Eimer“ und vergleicht erst dort mit equals. Gleiche Objekte müssen deshalb denselben Hashcode haben.

Frage 3 Welche Regel muss für equals und hashCode gelten?

Erklärung: Deshalb verwenden beide Methoden dieselben Attribute, z. B. mit Objects.hash(…). Ungleiche Objekte dürfen zufällig denselben Hashcode haben – das ist nur langsamer.

Frage 4 Was unterscheidet ein TreeSet von einem HashSet?

Erklärung: Das TreeSet ordnet nach compareTo bzw. dem Comparator ein. Dabei gelten Elemente mit Vergleichsergebnis 0 als Duplikate.
